## 实施记录（四项逐条）

### 1. 协调者计时器：子代理运行期间持续计时，全部子代理结束才停

- **语义修订**：协调者会话的「本次/累计」计时从「轮级」（轮结束即停）改为**覆盖整段编排**——
  协调者派发后轮末若仍有子代理在执行（activeSubagents 有 status:"run"），`turnStartedAt` **不折算不清零**，
  顶栏时钟持续走（等待子代理的空窗也计入「本次」与「累计」）；直到最后一个子代理离开 run 态且协调者
  自身空闲，才折入 `runMs` 并广播 state（前端时钟即时停）。期间报告送达/用户插话开新轮**接续同段
  「本次」不重置**（startTurn 只在 `turnStartedAt === null` 时起算）。
- **实现**（三件）：
  - `session-lifecycle.ts` startTurn：起算加 null 守卫（编排期新轮接续）；finally 折算分支加
    `waitWorkers` 判定（协调者且有 run 态子代理 → 保持计时）。
  - `session-runtime.ts` 新增 `settleCoordinatorClock(sh, rt)`：busy=false、无 run 态子代理、
    turnStartedAt 非空 → 折算 + 清零 + 广播 state（运行时已被替换/会话已删时只本地折算不广播）。
  - 收尾路径挂 settle：`runOneTask` idle 出口 + `finishSubagent` / `finalizeArchive` 尾部
    （覆盖归档请求/强制归档/打断/装配失败/休眠归档全部收尾形态；`requestArchiveWorker` 的空闲归档
    走 finalizeArchive 同被覆盖）。
- **不变量**：普通会话与无子代理的协调者轮语义**零变化**（轮间必为 null）；`busy` 语义不动（编排等待期
  busy=false，插话/新建对话照常）；最后报告送达开新轮时「累计」无缝衔接（settle 先折算、startTurn 再起算）。
- 顶栏 #clock tooltip 同步新语义。测试：`session-runtime.test.ts` 3 项（保持/接续/普通会话不变）。

### 2. 子代理抽屉列表行：计时器与上下文百分比上移第一行，与名称并排

- **行布局改为两行结构**（`drawer.js` + `index.html` CSS）：
  - 第一行 `.st-name`（flex）：**名称 + #id + ⏱ 计时 + 上下文 N%**——计时/上下文徽标 `margin-left:auto`
    推到行尾对齐、不收缩不折行，名称可收缩省略。run 态计时本地 1s 滴答（黄色高亮），其余态显示累计。
    上下文徽标超档位时附 ⚠（warn 黄 / cut、arch 红，完整档位说明收进 title 悬停）。
  - 第二行 `.st-meta`：`listMetaText(row)`——与 `subMetaText` 同源但**去掉用时/上下文段**（已上移），
    消息不重复；详情页头部与过程时间线收尾注仍用全量 `subMetaText`。
- 计时滴答（`tickClock`）与 2s 上下文轮询（`refreshRowMetaInPlace` → `setRowBadges`）改为**就地更新
  `.st-timer` / `.st-ctx`**，不整列重渲染（沿用 docs/11 W2 的阅读位置保持约束）。
- 验证：浏览器冒烟几何断言（名称/计时/上下文同一基线、meta 在第二行、徽标贴行尾、无溢出）。

### 3. 子代理/会话输入 token 为 0 与各家 provider「计算不同」——四家端点实测形状对齐

- **实证**（真实端点流式探测，2026-11-18；用档 `~/.ZQQ-harness/providers.json` 全部五项配置）：

| 端点 | prompt 实值位置 | 缓存命中字段 | 思考字段 |
|---|---|---|---|
| DeepSeek（openai） | 末 chunk `usage.prompt_tokens` | `prompt_cache_hit_tokens`（私有）+ `prompt_tokens_details.cached_tokens` | `completion_tokens_details.reasoning_tokens` |
| GLM（openai 格式） | 同上 | **仅** `prompt_tokens_details.cached_tokens`（此前漏读） | 同上 |
| MiMo（openai 格式） | 同上 | 无（`prompt_tokens_details: null`） | 同上 |
| GLM（anthropic 格式） | **`message_start.usage.input_tokens` 恒为 0 占位，实值只在末尾 `message_delta.usage.input_tokens`**（此前只读 message_start → 输入恒 0） | `cache_read_input_tokens`（message_delta） | 无独立字段（含在 output 内） |

- **根因**：真机坏档（4b49 会话，provider=glm-5-3-flash-anthropic）整个会话输入 token 全 0——连主对话
  都是 0，与子代理管线无关，纯属 anthropic provider 的 usage 提取只认 message_start。
- **修复**（两个 provider 各一处）：
  - `modules/providers/anthropic/provider.ts`：`message_delta` 用量兜底合并——`input_tokens`/
    `output_tokens`/`cache_read_input_tokens` 逐字段择新覆盖（官方端点 delta 只带 output，兼容端点
    全带，两侧形状都齐）；`usage` 缺席（畸形流无 message_start）就地补建，不丢用量。
  - `modules/providers/openai/provider.ts`：缓存命中两套字段并存——DeepSeek 私有
    `prompt_cache_hit_tokens` 优先，OpenAI 风格 `prompt_tokens_details.cached_tokens` 兜底（GLM 等
    兼容端点只有后者，此前漏读 → 缓存命中恒不计、与 DeepSeek「计算不同」）。
- 测试：anthropic 2 项（兼容端点 0 占位覆盖 / 畸形流补建）+ openai 3 项（两套缓存字段 / 无缓存字段不虚构）。
- 注：**已产生的坏档数据无法回填**（历史 totals 与子代理记录里 prompt=0 是当时端点返回的实况）；
  修复后新会话起输入/缓存命中恢复正常口径。

### 4. 重启后休眠待命的子代理显示「运行中」且无法归档——前端状态修正 + 休眠记录直接归档

- **根因**（两处）：
  1. 前端 `syncDrawer`：重建行时 `ensureDrawerRow` 缺省 status="run"，而 `rec.state === "idle"` 分支
     `continue` 前**没有把行定到 idle**——重启后休眠待命子代理显示 ▶ 运行中（⏹ 可点但后端无句柄，
     点击报「没有匹配的活动子代理」；归档按钮虽显示但同因失败），直到协调者 followup 复活它才恢复。
  2. 后端 `applySubagentControl` 只查 `rt.activeSubagents`（运行实例不跨重启存活）——休眠待命记录
     （`rt.subagents` 里 state:"idle" 的可复用记录）没有任何归档入口。
- **修复**：
  - `drawer.js` syncDrawer：idle 记录分支先 `row.status = "idle"` + 清 taskStartedAt（活实例在时下方
    activeSubagents 回填照旧覆盖为 run/idle；不在 → 末尾统一标 stale 的既有逻辑现在落在正确的 idle 态上）。
    行显示 💤「空闲待命 · 服务重启过 · 派任务时自动唤醒」，⏹ 隐藏、📦 可用。
  - `subagents.ts` applySubagentControl：archive 无活动匹配时**回落休眠待命记录**（reusable 且
    state:"idle"，按 subId/name 匹配）——`subagent-records.ts` 新增 `archiveDormantRecord`：记录就地
    定格 state:"archived" + archived 事件（前端行翻 📦）+ ui 路径状态通知送协调者收件箱 + 落盘。
    stop 不回落（休眠没有运行实例可打断）。`SubagentControlIo` 接缝（broadcast/deliver/persist）由两处
    调用方装配：createRuntime 工具闭包（sh）与 web-sessions 路由（host——deliver 复刻
    deliverToCoordinator 语义）。不再要求「先复活才能归档」。
- 家族行数哨兵：新增逻辑落 `subagent-records.ts`（休眠归档与 finalizeArchive 同族），subagents.ts 压注释
  回到 ≤400 行。
- 测试：subagents.test.ts 2 项（休眠归档四件套副作用 + stop 不回落/io 缺席降级）；浏览器端到端冒烟
  （隔离 USERPROFILE 实例装载含 idle/archived/error 记录的协调者会话档：行状态、按钮显隐、点击 📦 后
  行翻「已归档（只读） · 共 3 次任务 · 9 轮 · 输入 1234 / 输出 567 tokens」全部符合预期）。
