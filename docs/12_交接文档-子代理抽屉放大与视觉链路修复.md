## 0. 需求拆解（用户原话）

> 1. 「我还需要把子代理显示改进：增加放大选项，点击后子代理详情占满整页，再点击缩小则回到侧边抽屉」
> 2. 「检查视觉能力，我把图片直接从普通对话输入，模型无法识别，对于视觉能力模型，应该要有直接识别图片的能力，图片能和文字一起输入，视觉模型应该优先使用自身视觉能力，而不是使用视觉工具。」
> 3. （补充）「图片输入可以从对话框直接粘贴或者模型自己读取（视觉模型的话）」

### 0.1 B 排查结论（真修复，不是加功能）——三层缺口，第一层是主犯

docs/10 R3 声称「有视觉能力的模型直看图片」，真机实测不成立。逐层排查：

| 层 | 缺口 | 证据 |
|---|---|---|
| **机械断点（主犯）** | **server.ts 瘦壳适配器丢参**：`SessionHost.startTurn(rt, text, images?)` 签名有 images（docs/10 加的），但瘦壳装配写的是两参箭头 `startTurn: (rt, text) => startTurn(shell, rt, text)`——`/api/chat` 调 `host.startTurn(rt, text, images)` 时 **images 被静默丢弃，图片从未进入 history、从未到达模型**。TS 允许少参函数赋给多参签名 → typecheck 不报 | e2e 反证：还原两参箭头后，桩端点收到的 user 消息是**纯文本**（无多模态数组）；修复后是 `[{type:"text"},{type:"image_url"}]` |
| 行为缺口 | 系统提示对图片**只字未提**；view_image 描述还写着「有视觉能力时也可用它借用更强的视觉模型」——**主动引导有视觉的模型绕工具**。模型即使收到图也倾向答「无法识别/请用工具」 | sections.ts 全文无「图片/视觉」；旧工具描述原句 |
| 体验缺口 | 粘贴板粘贴无响应（docs/10 明确「不做粘贴」）——用户「直接输入图片」的自然方式（Ctrl+V 截图）落空 | 前端只有 📎 file input 一条入口 |

docs/10 真机验证只到「页面五元素 + providers 路由」，**没有验过多模态请求形状**——这是断点漏网的原因；本轮 e2e 脚本（§1.5）即为此补的回归网。

### 0.2 A 排查结论

纯新增 UI 能力，无存量 bug。约束：docs/11 W2 刚修好详情页「跳变」——放大/缩小**绝不能走整抽屉重渲染**（renderDrawer → renderDrawerDetail 会 renderSeq++、拆时间线重建），否则阅读位置/展开态又丢。定案：**只切 class 不重渲染**，DOM 原地保留。

### 0.3 定案总表

| 项 | 定案 |
|---|---|
| A 放大形态 | `#subDrawer.max` 固定全屏覆盖（`position:fixed; inset:0; z-index:30`，盖过侧栏/顶栏/聊天列/输入区；id+class 优先级高于窄屏媒体查询——两种屏宽均为真全屏）；列表/时间线**居中限宽 1000px**（整行铺满宽屏难读） |
| A 切换机制 | `setDrawerMax(on)` 只切 class + 按钮文案（⛶ 放大 ↔ ⤡ 缩小），**DOM 不动、内容零重建**；贴底跟随者显式送回底部（宽度重排后高度变化）；浏览器验证内容块数恒 9 |
| A 出口（三个） | ⤡ 缩小按钮 / **Esc 键**（全屏态盖住了顶栏与输入区，键盘出口保底）/ 出现审批卡自动缩回（审批卡在聊天列里，盖着会让会话卡在待批准） |

| B1 修复丢参 | server.ts 适配器改三参透传（248 行不变） |
| B2 提示词指引 | `SectionContext.vision?: boolean`（会话提供方勾了视觉才 true）→ base 段注入**图片直看指引行**：普通/worker 版（已直接看到原图、优先自身视觉、「不要声称看不到」、view_image 只用于磁盘文件且不对消息图调用）；协调者版（无 view_image 工具——只说明直看与子代理分工）。**缺省/false 不注入（存量 golden 零改动）**；AgentDeps.vision + `Agent.setVision(v)` 热更（applyProvider 换提供方时重建系统提示——原先 setProvider 不重建，vision 行会漂移，本轮补上）；worker（subagents.ts）与父会话同提供方同源接线 |
| B3 view_image 自身视觉优先 | 新接缝 `SystemToolDeps.selfVision?(): ProviderConfig | null`（会话自身提供方勾了视觉 → 其配置）；view_image 选型 **selfCfg ?? visionCfg**：有自身视觉直接用本会话模型读（**免配视觉模型即开即用**），无自身视觉才借用用户配置的视觉模型（docs/10 原路径）；结果尾注区分「本会话模型 X 自身视觉」/「视觉模型 X」；工具描述重写（删「有视觉也可借用」误导句，明确消息图 vs 磁盘图边界）；未配置文案改为「无法看图——当前模型没有视觉能力，且未配置视觉模型…」 |
| B4 粘贴收图 | `#input` paste 事件 → 剪贴板图片文件走 **addImageFiles 公共管线**（📎 选文件同一校验：≤4 张/≤5MB/四类 mime/base64/预览条）；**门控 `state.vision === true`**（与 📎 按钮一致——无视觉端点收多模态会 400）；纯文本粘贴不受影响（无图片项不拦截默认行为） |

### 0.4 明确不做（边界）

- 放大态不提供「宽度拖拽调节」（要的是整页阅读，不是分栏微调）；不做放大态下的双栏并列。
- 不把 view_image 的结果图注入对话历史（多模态 tool result 在 OpenAI 兼容端点不可移植——结果仍是文字描述，只是**分析者换成会话模型自身**）。
- 粘贴不做「非图片文件」（剪贴板文本走默认粘贴）与「跨会话暂存」。
- 协调者插话带图仍不做（docs/10 边界：interim 纯文本）；worker 任务书带图仍不做。
- view_image 选型**不提供用户级开关翻转优先级**（用户明确要求自身优先；要借视觉模型就给无视觉的会话用，或在提供方管理里把 visionProvider 指过去——自身无视觉时自然走借用路径）。

### 1.5 真机端到端验证（全过）

1. **视觉链路 e2e（新脚本 `scripts/e2e-dbg-vision-stub.mjs`，零 token，可重复跑）**：自包含「记录桩端点 + 隔离 USERPROFILE 起服务 + API 驱动 + 断言」。7 项全过：绑定工作区 / 带图 chat 202 / **系统提示含「图片输入」指引行与「不要声称看不到」** / **user 消息 content 是多模态数组** / text 部分为原提问 / image_url 为完整 `data:image/png;base64,<原样>` data URI。**回归网反证**：临时还原两参箭头重跑 → 精准失败于「content 是多模态数组」（实收纯文本）——证明脚本锁的就是这个断点；随后恢复修复（grep 确认）。
2. **抽屉放大浏览器冒烟（liveview 桩 + 隔离环境 + IAB 驱动）**：侧栏 420px → 点「⛶ 放大」→ `.max` + `position:fixed` + rect `0,0×1280×720`（=视口）+ 时间线 1000px 居中（left=140）+ **内容块数恒 9（零重建）** + 贴底保持；`#input` 上按 **Esc** → 回 420px 侧栏；再放大 → 点「⤡ 缩小」→ 同样恢复；**列表页放大/缩小**同样可用；放大态点 ✕ 收起 → 重开**不继承放大态**。
3. **放大态视觉审查**（截图 + 视觉模型判读）：全屏覆盖无底层露出 / 头部按钮齐全（← 列表、⤡ 缩小、✕）/ 时间线居中两侧留白约 1000px / 无文字重叠溢出错位（唯一备注：滚动条与底部运行提示贴近——布局密度观感，非缺陷）。
4. **粘贴链路**：无视觉会话（桩 provider 未勾 vision）合成粘贴 → **不收图**（门控生效，预览条保持隐藏）；勾 vision 重启后 → 启用态输入框合成粘贴 → **预览条收 1 张图**（正路径）→ 点 ✕ 删除恢复隐藏。备注：IAB 对预览条右上角 -7px 偏移的删除小按钮有可点性检查超时（playwright actionability），页内 click 正常——真实手点无碍。
5. 过程坑（诚实记录）：①e2e 脚本首版 cwd 推导错（URL pathname 带前导斜杠）与「读后追加」在文件不存在时崩——改 fileURLToPath + appendFileSync；②browser `body.press` 在 IAB 报 active element 失配——改按 `#input`；③服务重启后初始视图为空引导态（无工作区）——「粘贴过了门控但 📎 隐藏」一度像矛盾，实为 noWs 既有逻辑（state.vision 来自 active provider 与视图无关）；点会话行恢复视图后正路径复验通过。

### 1.6 已知边界（诚实声明）

1. **「少参适配器」这类丢参 TS 不报**（少参函数可赋多参签名）——防御只能靠 e2e 请求形状回归网（e2e-dbg-vision-stub.mjs，手动跑，未挂 CI/npm script）。
2. 放大态 z-30 盖住全页（含顶栏/输入区）是设计——Esc/⤡ 是出口；审批卡自动缩回覆盖了唯一「阻塞型」交互（审批不答会话卡死）；⏹ 停止按钮在放大态不可达（先缩小再停，Esc 一步）。
3. 粘贴门控只看 `state.vision`；无视觉会话的 disabled 输入框真实粘贴本就不可达（合成事件除外——只用于测试）。
4. worker 系统提示同样注入视觉指引行（worker 与父会话同提供方）；文案用「消息可能直接携带图片」兼容任务语境（任务书带图仍是不做项，docs/10 边界）。
5. view_image 自身视觉 = 用本会话 provider **单独发起一次多模态 chat**（不进会话历史，与借用路径同构）——不是把图注入对话；「模型自己读取」的语义落点是分析者换成自身，交互形态不变。
6. vision 行随提供方热切换进出系统提示（applyProvider → setVision 重建）——系统提示字节随会话配置确定，golden 按 vision 有无两个变体锁定。
