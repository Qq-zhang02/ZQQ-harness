## ⭐ 实施记录（2026-09-25，增量特性：edit_file 新增 occurrence——同文多处只改其一）

`npm run typecheck` 通过；`npm test` **219 项全绿**（新增 2 项：file-tools 机制级 + edit-file 工具级，并扩展多命中报错断言）。起因是用户实测：文档中不同位置内容完全相同的部分无法区分改写——此前模型只能"扩大上下文凑唯一"，凑不出就只能退到 run_pwsh 跑脚本按次替换（绕开先读后写台账/原子写/审批矩阵三条保护，且 read-only 模式下该路会被沙箱拒绝）。

- **设计**：`applyEdit` 增可选第 5 参 `occurrence`（1 起始整数，按文档顺序数第几处命中）；edit_file 工具 schema 增 `occurrence: integer` 并透传（模型传字符串数字也容忍，Number 归一后由整数校验把关）。实现基于既有 `split(needle)` 的 parts 数组：第 k 次命中位于 `parts[k-1]` 与 `parts[k]` 之间，替换 = `parts.slice(0,k).join(needle) + newStr + parts.slice(k).join(needle)`——未选中命中与前段全部原样保留，count 回 1（工具回传"替换 1 处"）。CRLF 世界语义不变（先 toLf 匹配、写回 applyEol 还原）。
- **校验次序**：old 空串/old==new → replace_all 与 occurrence 互斥 → occurrence 须 ≥1 整数 → 未命中 → 多命中且未给 occurrence（报错文案三种消歧方式并列，含 occurrence 与范围 1–N）→ occurrence 越界（报实际次数与合法范围）→ 执行。越界报错带 `1–N` 帮模型自纠。
- **报错文案即提示工程**：多命中报错从"补上下文或 replace_all"扩为三选项并列（补上下文首选 / occurrence 指定第几处并提示配合 read_file 行号数次序 / replace_all），模型无需额外说明即会选用。
- **边界**：occurrence 与唯一命中兼容（count=1 时 occurrence=1 等价普通替换）；与 CRLF/台账/审批矩阵全部正交（编辑后台账 noteFileRead 更新，可连续编辑无需重读）；Office 等二进制文档不适用（本就拒绝、指向 run_pwsh，维持原语义）。

**设计落点（沿模块化范式，方便后续增删改）**：

- 四个新系统工具各自独立模块：`tools.read-file` / `tools.write-file` / `tools.edit-file` / `tools.mcp-manage`（SystemToolDef + modules.ts 一行登记，删能力=删一行）。共享机制下沉 **core/file-tools.ts**（路径解析/已读台账键/EOL 归一/二进制嗅探/原子写/精确编辑/写入裁决矩阵）；mcp.json 严格层独立为 **src/mcp/config.ts**。
- **与 manager.ts 宽松层刻意分层**：会话启动走 loadMcpConfig（坏文件静默跳过，保证能启动）；manage_mcp 的写入路径走 config.ts 严格层（损坏文件 fail-closed 拒改——宁可让模型报告"文件已损坏请人工修复"，绝不覆盖）。两层并存是分层语义，不是重复。
- **SystemToolDeps seam 扩 4 成员**：`mcpStatus()`/`reloadMcp()`（web 壳实现 reloadMcpFor：整体断开→合并重连→setMcpInstructions→广播 state）；`noteFileRead()`/`fileWasRead()`（createRuntime 闭包内 Set，ledgerKey 在 Windows 做大小写归一）。
- **Agent 热更新两处**：`setMcpInstructions()`（对称 setSkills，重建系统提示保留历史）；run() 的工具 schema 从"每轮 run 取一次"改为**每轮循环内重取**——manage_mcp 重连后新 MCP 工具下一轮即可调用，token 估算与请求同源。

**与设计的差异/裁决（以代码为准）**：

- **先读后写台账放 SystemToolDeps** 而非三工具共享闭包——三工具是三个独立模块，无法共享实例状态；"read_file→write_file/edit_file 前置凭据"是会话级状态，归 seam（skills() 同款理由）。
- **文件写裁决矩阵**与 run_pwsh 信任边界等价但一步到位：workspace-write 区内直写、区外弹卡；read-only 一律弹卡；danger-full-access 不约束（逐条确认才弹）。不经过 pwsh 那种"OS 沙箱拒绝→justification 升级→审批"两步路径——文件工具的写目标在调用时即已知，无需 OS 裁决；审批词汇/fail-closed 语义完全复用 approval/types.ts。
- **edit 的 CRLF 策略**：匹配与替换在 LF 世界进行，写回还原文件既有换行（detectEol→applyEol）；read_file 按 LF 展示。write_file 内容原样落盘。
- **write_file 覆写守卫是绝对的**：已存在文件必须本会话 read_file 过（二进制/超大这类读不了的目标也拒绝并指向 run_pwsh），新文件不受限；edit_file 同前置。
- **manage_mcp 校验次序**：先 validateServerEntry（服务名≤64 无空白/控制字符、args 字符串数组、env 字符串 map、type 须已注册传输）再 buildServerConfig（构造会对入参做展开，脏入参不能先进构造）；原子写 tmp+rename；未知顶层键与其他服务器条目原样保留；list 恒展示全局+工作区两份（损坏标注、互不妨碍）。
- **冒烟产物语义（既有行为，记录备查）**：`/api/stop` 的 abort 打不断挂起中的审批 promise——先 stop（置 abort）再决议当前卡，轮才收尾；switch 分支开新会话不记 recentWorkspaces（仅 bind 分支记），session order.json 会留下空工作区键（本次已手工清）。

## 2. DSH（deepseek-harness）参考与取舍

DSH 是 60+ 包的 monorepo，构建在 vendored Cordis 插件框架上，官方定位："Everything is a plugin... There is no privileged core to patch"（docs/architecture.md）。

**借鉴（思路层面）**：

| DSH 做法 | 证据 | 本项目落地 |
|---|---|---|
| 一切皆插件，组合清单定义产品 | `packages/bundle/base/cordis.patch.yml`（60+ 行，每工具/适配器一行） | `src/modules.ts` 组合清单（TS 数组代替 YAML） |
| 注册即 effect，返回精确 disposer | `ctx.tools.register` / `llm.registerAdapter`（可逆、支持卸载） | 泛型 `Registry<T>`，`register()` 返回 `() => void` |
| 接口包/实现包强制分离（capability seam） | `sandbox`(abstract) vs `sandbox-local`；`session-persistence` vs `-jsonl` | 接口进 `src/core/types.ts`，实现进 `src/modules/*` |
| 系统提示 section 化 + 全局序号表 | `core/system-prompt` 的 `SECTION_ORDERS` | `promptSections: Registry<PromptSection>` + order 字段 |
| 能力用声明代替分支 | adapter 注册 `registerAdapter(providers, adapter)` | provider 格式注册 + 思考能力声明字段 |
| 配置 schema 即代码、阈值单一出处 | schemastery `static Config` | config.ts 单一出处 + `/api/meta` 下发前端 |
| 每步迁移一个包、旧格式只读兼容 | `session-format-v0-to-v1`…`v3-to-v4` | 存档格式只加可选字段；分阶段每阶段独立可回滚 |

**不借鉴（并说明原因）**：
- **Cordis 框架 / pnpm monorepo**：项目体量（~4300 行 TS）撑不起 60 包；type-stripping 直跑 + 零依赖是核心优势，引入框架即放弃。用 ~100 行手写注册中心获得 80% 收益。
- **YAML patch / profile / bundle**：组合复杂度远超需要，TS 清单 + （远期）harness.json 开关足够。
- **typert Remote / Host-Client 物理分离**：单文件前端 + 本机 SSE 已够用，只抽取"事件名单一出处 + 契约测试"。
- **会话事件溯源（append-only log + 投影）**：ZQQ-harness 的 sessions = JSON 存档、messages = surface 是刻意取舍（见 compaction.ts 头注释），不做架构级更换。

### 4.1 泛型注册表（registry.ts）

```ts
export type Disposable = () => void;

/** 按名字注册/注销；all() 按名字稳定排序（保证 schema 输出与系统提示字节稳定）。 */
export class Registry<T extends { name: string }> {
  private items = new Map<string, T>();
  register(item: T): Disposable {
    if (this.items.has(item.name)) throw new Error(`重复注册：${item.name}`);
    this.items.set(item.name, item);
    return () => { this.items.delete(item.name); };
  }
  get(name: string): T | undefined { return this.items.get(name); }
  require(name: string): T { /* 取不到抛错 */ }
  all(): T[] { return [...this.items.values()].sort((a, b) => a.name.localeCompare(b.name)); }
  names(): string[] { return this.all().map((t) => t.name); }
}
```

要点：重复注册抛错（现 ToolRegistry 是静默覆盖，mcp 重连依赖 remove+register——MCP 工具**不经此 Registry**，见 4.7）；排序稳定（token 计数、系统提示、契约测试都依赖字节稳定）。
