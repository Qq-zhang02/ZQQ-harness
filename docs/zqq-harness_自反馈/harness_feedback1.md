## 2. 问题与改进建议（按层面）

### A. 工具层

**A1 [P0] `run_pwsh` 超时后无任何进度信息**（#4）
- 现象：999 次置换 × 多组 Mantel/PERMANOVA/db-RDA + 零模型脚本超过 300 s 上限被杀，返回 `exit code: unknown`、stdout 为空，`print(flush=True)` 的进度也丢失。
- 影响：不知道脚本跑到哪、是否留下半成品文件；只能重跑并拆分。
- 复现：任何 >300 s 的计算脚本。
- 建议：超时时返回已捕获的部分 stdout/stderr 与子进程 PID；允许更长 timeout 或"后台运行 + 日志轮询"；默认 `PYTHONUNBUFFERED=1` 并把 stdout 实时落盘到工作区日志。

**A2 [P0] `read_image` 图片块永久占用上下文**（#4 #5）
- 现象：每轮携带 10+ 张高清图（单张 100–700 KB）；R2 共读图约 17 次，R1 后期"每轮 token 沉重"，直接触发"上下文过长预警"。
- 影响：被迫"每图只读一次"，R2 fig_R2_3/5 的轻微瑕疵（y 标签裁切、表头重叠）最终未复看。
- 建议：降采样预览（最长边 ~1200 px）；"只看一次/事后丢弃"选项；允许用 `view_image` 借外部视觉模型替代原生读图；提供"图件自动体检"（空白占比、文字越界、重复图例）减少一半读图。

**A3 [P1] edit_file/write_file 的"本会话已读"校验跨会话失效**（#4 #5）
- 现象：唤醒后覆写/编辑自己创建的文件被拒（"已存在且本会话未读取过"）。
- 影响：每次唤醒多一次 read_file 与上下文。
- 建议：对子代理自建文件豁免重读校验，或允许以 mtime 为已读凭据；在唤醒消息中恢复"已读台账"。

**A4 [P2] `edit_file` 漏传 `path` 两次被拒**（#4 #5）
- 现象：报"缺少必填参数 path"，纯返工。
- 建议：参数校验前置到调用生成阶段，或在工具 schema 中强化必填提示。

**A5 [P2] `run_pwsh` 输出失控与 ANSI 码**（#4 #5）
- 现象：正则误写导致打印 ~40k 字符被系统截断存盘；stdout 混入 `[31;1m` 等颜色码。
- 建议：默认限制 stdout 行数并提示"已截断 N 行"；剥离 ANSI 颜色码。

**A6 [P2] "只报告"类任务缺少无写入模式**（[协调者]）
- 现象：用户要求子代理"只报告不写文件"，只能靠任务书文字约束。
- 建议：agent_task / agent_followup 增加 `dryRun`/`readOnly` 选项，运行时禁用 write_file/edit_file 与写入型 run_pwsh。

### B. 平台层

**B1 [P0] 中断无预警、无"死前摘要"**（#4 #5）
- 现象：429 频率限制、5 小时上限、用户打断均直接结束任务；子代理在修图排版或 run_pwsh 超时后被动中断，无任何预警。
- 影响：唤醒后靠协调者任务书里的"已保留/剩余清单"才知道做到哪。
- 建议：中断前自动写 `progress.md`（最后成功的脚本/图/表、下一步、已查看图片清单）并在唤醒时注入；在额度接近上限、上下文接近阈值时提前提示子代理"保存进度、停止读图、改写文档"。

**B2 [P0] 唤醒后状态不透明**（#4 #5 [协调者]）
- 现象：不知道哪些 read 记录、已看过的图、已确认的排版结论仍有效；不知道哪些文件被他人改动。实际发生了：R2 的 `key_numbers_all.md` 在中断期间被 #9 重写为仅含 08 节；R1 的 `04_env_assembly.py` 被 #8 改写向前选择逻辑。
- 建议：唤醒消息列出"保留的已读台账/已查看图片清单"与"自上次以来被修改的文件（mtime 对比）"；协调者控制工具在唤醒时自动附带。

**B3 [P1] "死前进展"摘要失真**（[协调者]）
- 现象：失败报告的"写入文件"列表混入脚本源码片段（如 `with open(c.TAB / "tab_R1_4_env_spearman、first_ax_of_block = {}`），无法据此判断真实产出。
- 建议：修正摘要生成逻辑，只列真实路径；补"最后成功脚本编号"。

**B4 [P1] 额度状态不可见、并发与速率限制不联动**（[协调者]）
- 现象：默认并发 4 在约 15 分钟后触发 429 频率限制；之后又触发 5 小时上限（报错含重置时间，但协调者事前无法得知余额）。
- 建议：subagent_status 显示额度/重置时间；派发回执在接近阈值时警告；`subagentMaxConcurrent` 随速率限制自动下调；429 文案统一区分"频率限制"与"使用上限"并给出建议动作。

**B5 [P1] 上下文过长预警的处置与用户意愿冲突**（[协调者]）
- 现象：系统建议 >25% 即"归档重派"，但用户明确要求保留原实例继续；新实例 #8/#9 在被停止前已改动原实例的文件，造成潜在冲突。
- 建议：预警同时给出"精简操作"任务书模板（合并脚本、少读图、只写文档），允许协调者选择"继续原实例"并在这种情况下**不派新实例写同一目录**；若已派，停止后要向原实例说明改动。

**B6 [P2] 状态消息重复**（[协调者]）
- 现象：#4 被打断的状态消息连续送达 5 次。
- 建议：去重合并。

**B7 [P2] `read_archive` 成本高**（[协调者]）
- 现象：新实例接续需读 120+ 次工具调用的存档，token 成本高于直接看磁盘文件。
- 建议：提供摘要版存档（决策与路径索引），完整版按需展开。

### C. 任务书 / 协调层

**C1 [P1] 依赖未冻结**（#4）
- 现象：任务书写 `work/shared/` "可能没有、不可用则自建"，中途出现后又要求"以共享版为准"。
- 影响：R1 重写 ztyle.py 并重跑 01/02。
- 建议：开工前由协调者冻结依赖（shared 就绪后再派），或明确"后出现的 shared 不追溯"。

**C2 [P1] 并发与"调用预算"未前置**（#4 #5）
- 现象：最初无并发限制，中途要求"合并脚本、控制请求频率"；R1 已写细粒度脚本 01–07，被要求合并成 2–3 个。
- 建议：任务书开头给出并发数、允许的 run/读图次数、脚本粒度。

**C3 [P1] 关键语义未定义**（#5）
- 现象：CK 是"演替终点"还是"对照"影响分类规则——严格对称下 late 关联 MAG 仅 38 个而 ck 关联 302 个，需额外增加 "ck&late" 类才能自洽；"strict 24" 无定义，R2 测了约 30 个候选（top6_union=24、top24_global_mean=24、TPM≥600=20、rel≥0.1%=28）只能给候选表。
- 建议：任务书预先说明 CK 语义与分类规则；写明"无法唯一确定时输出候选表并以未决问题上报"。

**C4 [P2] 命名规则与临时脚本目录**（#4 #5）
- 现象：编号要求"连续"但中途插表（16b/19c）不知是否允许子编号；R2、R4 的探索脚本写到了 `work/_scripts/`，严格说超出"只写 results/Rn/"。
- 建议：明确子编号规则与统一的临时脚本目录（如 `work/_scratch/<subId>/`）。

**C5 [P0] 多实例写同一目录的冲突预防**（[协调者]）
- 现象：按预警派新实例 #8/#9 接手 R1/R2，随后按用户意愿停新留旧；期间 #8 已改 R1 脚本、#9 已重跑 R2 脚本 08。
- 建议：控制工具在"同一 scope 已有待命/归档实例"时提示协调者优先唤醒而非新派；任务书模板加入"接手前核对他人改动"。

### D. 环境层

**D1 [P1] 统计库缺失**（#4）
- 现象：`python` 3.8 无 scikit-bio/vegan，BC/PCoA/PERMANOVA/PERMDISP/Mantel/db-RDA/向前选择/RCbray/NST 全部自写并自测（约 300 行），是最大额外工作量。
- 建议：预装 scikit-bio（3.8 与 3.14），或在 `work/shared/` 提供 stats 工具脚本。

**D2 [P2] 版本坑清单**（#4 #5）
- numpy 1.24：`np.r_["", arr]` 报 "unknown special directive"；`np.minimum` 对 NaN 传染（q 值全 NaN，星号消失，返工一轮）。
- pandas 2.3：`groupby(axis=1)` 弃用、`SeriesGroupBy.agg("n")` 不存在；`iterrows()` 中 `r.rank` 解析为方法而非列，导致整个 DataFrame 被画进图（4.6 MB 乱码图）。
- scipy：`kruskal` 对 categorical groupby 需 `observed=True`。
- matplotlib 3.7.5：`annotate(arrowprops)` 载荷箭头部分不渲染（改 `FancyArrowPatch`）；`axvline` 改变 imshow 的 ylim；20 列 GridSpec 的 wspace 以列宽为单位（改嵌套 GridSpecFromSubplotSpec）。
- 建议：子代理系统提示词加"行迭代一律用 `r['col']`"；在 README 中列出已知坑。

**D3 [P1] 共享样式副作用**（#4 #5）
- 现象：`ztyle.setup()` 默认 `figure.constrained_layout.use=True` 与显式 GridSpec/`subplots_adjust` 冲突；`group_labels` 含换行符使图例变高与标签重叠。
- 建议：README 列出全部 rcParams 键与副作用；多面板示例给出 `extra_rc={"figure.constrained_layout.use": False}`。

**D4 [P2] `KeyNum` 追加式写入不幂等**（#4 #5）
- 现象：`key_numbers_all.md` 追加写，重跑/并行会重复或覆盖，每次需手动删除重建。
- 建议：各脚本独立写 JSON，`run_all.py` 统一生成汇总 md。

### E. 子代理系统提示词建议（#4 #5）

1. 每完成一个脚本即写 `progress.md`；被中断/超时时知道如何留痕。
2. 唤醒后先跑 `run_all.py`（或核对 progress.md），而非逐个 `Get-ChildItem` 核对。
3. 行迭代一律用 `r['col']`，不用属性访问。
4. 读图前先确认脚本无异常输出；读图后立即用文字总结，每图只读一次。
5. 任务书给出"调用预算"时严格遵守；上下文接近阈值时主动停止读图、改写文档。
6. 允许子代理在无法唯一确定时输出候选表并以未决问题上报，而不是替用户假设。
