## 3. 踩坑记录（接力者必读）

1. **npm test 是显式文件清单**（package.json test script 逐个列 .test.ts）——新增测试文件必须同步登记，否则静默不跑（本次 http.test.ts 首跑就漏了，测试数对不上才发现）。
2. **杀测试服务器要用精确 PID**（`netstat -ano | findstr :端口` → `taskkill /F /PID <pid>`），不要 `taskkill /IM node.exe`——会误杀机器上所有 node 进程（本次失误已犯，见下"诚实记录"）。
3. **活服务器冒烟模板**：`USERPROFILE=$(临时目录) ZQQ_NO_BROWSER=1 PORT=18787 node src/web/server.ts`——临时 USERPROFILE 让 os.homedir() 指向空目录，绝不触碰真实 `~/.ZQQ-harness`（P8 实施记录的隔离方法，可靠）。
4. Git Bash 下 git 输出的 LF→CRLF warning 是 core.autocrlf=true 的正常提示，无害。
5. 改 sections.ts 提示词后**先跑 contract.test.ts 的 golden**——若渲染文本有意变更，更新 golden 快照 = 显式决定（本次设计为渲染不变，golden 零改动即通过）。

**诚实记录**：清理测试服务器时执行了 `taskkill /F /IM node.exe`，终止了 2 个 node 进程（测试服务器 + 早前后台测试残留）。若当时机器上还有其他 node 进程（如用户自己的 dev server）会被误杀。无法追溯确认，特此记录。

## 4. 剩余工作与接力入口（按优先级）

### 4.1 阶段 A 收尾：IMAGE_RULES（首项，预计 1-2 小时）

图片规则（≤4 张 / 单张解码后 ≤5MB / PNG·JPEG·GIF·WEBP）目前**四重定义**：前端 HTML accept 属性（`index.html` ~L418）、前端 `IMG_MIMES` 数组 + 校验文案（~L2218-2226）、前端按钮 title（~L414）、后端 `parseChatImages`（`src/modules/web-sessions/index.ts:14-35`）。收敛方案：

1. `src/config.ts` 导出 `IMAGE_RULES = { maxCount: 4, maxBytes: 5*1024*1024, mimes: ["image/png","image/jpeg","image/gif","image/webp"] }`；
2. 后端 `parseChatImages` 消费它（错误文案插值 `${IMAGE_RULES.maxCount} 张` 等，渲染不变）；
3. `metaSnapshot` 增发 `imageRules`；
4. 前端三处消费 meta：JS 校验（addImageFiles）用 `metaOf().imageRules`（meta 未到时禁用上传按钮或退回静态 accept——HTML 静态 accept 属性**保留**作为无 JS 降级，允许这一处保留字面量并加注释指向 config.ts）；按钮 title 在 applyState 里设一次。

验收：web-sessions.test.ts 补 imageRules 经 meta 下发的断言；手工冒烟（视觉会话传 4 张小图成功、第 5 张被拒）；376+ 测试全绿。
