# 操作手册：桌面端打包与冒烟（给自己看的速查版）

> 目标读者：本人。不求严谨全面，只求**照着抄命令就能做对**。细节原理在 docs/25（桌面方案）与 README「打包分发」节。
> 终端写法约定：手册里每条命令标注了适用终端——**PS** = PowerShell（Win 开始菜单搜 PowerShell），**GB** = Git Bash。两者任选其一，但同一条命令在两边写法可能不同，别混抄。

---

## 1. dist/ 文件夹里都有什么、什么用

每次打包后 dist/ 里会出现这些东西（版本号 0.1.0 会随 package.json 变）：

| 文件 / 文件夹 | 是什么 | 怎么用 |
|---|---|---|
| `ZQQ-harness-Setup-0.1.0.exe` | **正式安装包**（约 120MB）。双击进入引导式安装，可以选安装位置；默认装到用户目录、不需要管理员权限 | 发给别人 / 自己重装时用。装完开始菜单和桌面有快捷方式 |
| `ZQQ-harness-0.1.0-portable.exe` | **免安装便携版**（约 110MB）。单个文件，双击自解压直接运行，不在系统里留安装项 | 拷 U 盘、临时机器、不想装的时候用。缺点：双击后没有控制台日志，出问题排障不方便 |
| `win-unpacked/` | **解开的完整程序目录**（上面两个 exe 的内容就是它打包的）。里面的 `ZQQ-harness.exe` 双击即可运行 | 两个用途：① 打包后**快速验收**——直接跑里面的 exe，不用装；② 想看打包版出了什么问题时，从这里运行 |
| `ZQQ-harness-Setup-0.1.0.exe.blockmap` | 安装包的差量更新元数据（给 electron-updater 自动更新用的，目前没启用自动更新） | **不用管，可删** |
| `builder-debug.yml` | 打包工具的调试日志 | 不用管 |

安装/卸载的静默命令（装机自动化用，平时双击就行）——**CMD 或 PS**：

```
Setup.exe /S /D=C:\Tools\ZQQ          静默装到指定目录（注意：/D 后的路径不带引号、且必须是最后一个参数）
"Uninstall ZQQ-harness.exe" /S        静默卸载（在安装目录里执行）
```

卸载**不会删**用户数据（对话记录都在 `C:\Users\<你>\.ZQQ-harness\`，数据与程序分离——这是设计决定）。

## 2. 平台与依赖（哪台机器要装什么）

### 目标机（装 Setup.exe 或跑 portable 的机器——比如发给别人的电脑）

| 依赖 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 10/11 x64** | 硬性要求。沙箱是 Windows 受限令牌实现 + koffi 只有 win32-x64 预编译——**macOS/Linux 一律不支持** |
| PowerShell 7 | 装了并在 PATH（命令行敲 `pwsh -v` 有版本号） | **只影响 run_pwsh 工具**（AI 执行命令）：没装的话程序照常启动、聊天/文件工具照常，但 AI 一执行命令就报「无法启动 pwsh，请确认已安装 PowerShell 7」。注意要的是 **7.x（pwsh）**，不是系统自带的 Windows PowerShell 5（powershell.exe）；官网 GitHub Releases 装 Latest LTS 即可 |
| Node.js | **不需要** | Electron 自带完整 Node（24.x），服务就是用它跑的 |
| 浏览器 | **不需要** | Electron 自带 Chromium |
| 管理员权限 | **不需要** | 默认按用户安装；只有主动装进 Program Files 等受保护路径时 NSIS 才提权 |
| 网络 | 只在对话时访问配置的模型 API | 本地服务只绑 127.0.0.1，不监听外网 |

> 未签名的代价：首次运行 Setup.exe 可能被 SmartScreen 拦（点「更多信息」→「仍要运行」）；杀软可能误报 portable.exe。已知取舍。

### 开发机（改代码、打包的机器——就是本机）

| 依赖 | 要求 | 用在哪 |
|---|---|---|
| Windows 10/11 x64 | 同上 | 沙箱/FFI 都是 Windows-only，开发也只能在 Windows |
| Node.js | **≥22**（package.json engines 约定；.ts 靠原生 type-stripping 直跑，不编译）。本机 v24.19.0 ✓ | `npm test`、`npm run web`（node 直跑 server.ts） |
| PowerShell 7 | 同目标机 | `npm test` 里的 pwsh 沙箱用例 + 开发时真机测 run_pwsh。本机 7.6.10 ✓ |
| npm 镜像 | registry 已配 npmmirror | 装包不走外网；打包下载 Electron 另需两个 MIRROR 环境变量（见 §4） |
| electron / electron-builder | 已在 devDependencies，`npm install` 即得 | 打包用。若装包时 postinstall 被拦（Electron 二进制没下来），手动补：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js` |
| koffi | npm install 自动带 win32-x64 预编译 DLL | 沙箱 FFI，**无需自己编译**；打包时它会随 node_modules 进包（每期产物校验清单里有一项 `/api/meta` 200 就是验它） |

一键自检（**任意终端**，在项目根目录跑，全绿说明开发机依赖齐）：

```
node -v          应 ≥ v22
pwsh -v          应显示 7.x
npm -v           有版本号即可
```

## 3. 什么时候需要重建打包

只要改了任何**源代码**（src/、desktop/、public/ 里的文件），旧安装包里就是旧代码，想验证桌面版或发给别人，就要重建。**只改了 docs/ 或 README 不用重建。**

重建花 2–5 分钟（第一次慢，之后有缓存）。

## 4. 怎么重建安装包

### 第 0 步：进项目目录

在终端里 cd 到项目（下同，所有命令都在项目根目录执行）：

```
cd F:\MyClaw\ZQQ-harness
```

### 第 1 步：打包前先跑全量测试（别省）

**任意终端（PS / GB 通用）：**

```
npm run typecheck
npm test
npm run smoke:sa4
```

三项都绿（test 显示 `fail 0`、sa4 显示 `10/10 项通过`）才继续。

### 第 2 步：打包（一条命令，双镜像必带）

> 为什么带两个 `MIRROR` 环境变量：本机直连 GitHub 慢/不可达，打包要从 npmmirror 镜像下载 Electron 二进制。不带的话会卡死在下下载。

**PowerShell（PS）：**

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
npx electron-builder --win
```

**Git Bash（GB）：**

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
npx electron-builder --win
```

> 注意：GB 写法是「变量=值」前缀 + 反斜杠换行；PS 写法是先 `$env:` 赋值再执行。**别把 GB 的写法粘进 PS**（会报错）。
> 构建输出里会有几条警告（asar disabled / no code signing / default icon）——**都是已知取舍，不是错误**，最后新 exe 出现在 dist/ 即成功。

### 第 3 步：快速验收打包版（1 分钟）

双击 `dist\win-unpacked\ZQQ-harness.exe`（或终端里跑它），应看到：

1. 窗口几秒内出现，不白屏；
2. 左侧有工作区栏、顶部有模型徽标和设置项；
3. 关掉窗口后进程全部退出（任务管理器里搜 ZQQ-harness 应为 0 个）。

想更严格就按第 5 节的清单测。

## 5. 冒烟怎么做（三层，从便宜到贵）

「冒烟」= 粗但快的验证，确认主链路没断。按层做，越往下越接近真实使用。

### 第 1 层：自动测试（零成本，每次改代码必跑）

**任意终端，项目根目录：**

```
npm run typecheck      类型检查（两段都无红字输出=过）
npm test               450 项单元/契约测试（看结尾 fail 0）
npm run smoke:sa4      可观测性冒烟 10/10（零 token，自动起桩服务）
```

> 全自动，不需要 API key、不弹窗口。`smoke:sa2` / `smoke:sa3` / `smoke:subagent` 是更专项的零 token 冒烟（协调者/并行子代理），改到相关功能时才需要跑。
> `npm run smoke` / `smoke:anthropic` 是**真机**冒烟（要花 API key 的钱），发布前才跑。

### 第 2 层：开发模式人工看（改前端必做）

**任意终端：**

```
npm run desktop      开发模式起桌面版（Electron 窗口，带 [svc] 服务日志）
```

（不想开窗口也可以 `npm run web`，然后浏览器开它打印的 http://127.0.0.1:端口）

用眼睛+鼠标过一遍当前改动涉及的功能：切会话/发消息/开抽屉/设置模态等。**改完前端刷新页面即可生效**（no-cache）；但**新增** app/ 下的 .js 文件要重启服务才注册。

排障提示：桌面版出问题先看终端里的 `[svc]` 前缀日志（服务子进程的全部输出），这是主要信息源；portable exe 双击没日志是正常的，排障一律回开发模式。

### 第 3 层：打包版实测（每期发布前必做）

就是第 4 节的第 3 步 + 下面的完整清单。用 `dist\win-unpacked\ZQQ-harness.exe`（或真装一遍 Setup.exe，更接近用户）：

| # | 测什么 | 预期 |
|---|---|---|
| 1 | 启动 | 几秒出窗口，页面完整 |
| 2 | 绑工作区、开新对话、发一条消息（需配好带 key 的提供方） | 气泡出现、模型正常回答 |
| 3 | 让 AI 写**工作区外**的文件（如 `C:\temp\x.txt`） | 弹审批卡或被沙箱拒绝——不能静默写成功 |
| 4 | 开协调者对话派一个子代理 | 抽屉出现子代理行、过程可看 |
| 5 | 关窗（**先确认设置模态「🖥 桌面版」区托盘开关是关**） | 任务管理器 ZQQ-harness 进程清零；若开了托盘：关窗=隐藏到托盘（进程驻留），退出经托盘图标右键菜单 |
| 6 | 设置模态「🖥 桌面版」区（DT3，仅桌面版显示）：勾「最小化到托盘」→ 关窗 → 托盘图标出现、进程驻留；再开设置取消勾选 → 窗口自动唤回 | 托盘开/关即时生效；「开机自启」勾上后任务管理器→启动应用页应出现 ZQQ-harness（仅打包版注册；测完取消勾选清理） |
| 7 | （审批通知）运行中让窗口失焦，触发一张审批卡（第 3 步同款） | 系统通知弹出、点击回到窗口并见审批卡（Chromium 权限首次询问选允许） |
| 8 | （发布给别人时）卸载 | 程序没了，但 `C:\Users\<你>\.ZQQ-harness\` 对话数据还在 |

目标机还要加一条：**确认装了 PowerShell 7**（`pwsh -v` 有 7.x）——否则第 2 步里 AI 执行命令会报错（见 §2）。

没有 API key 时的替代：把 `scripts/e2e-sa4-stub-llm.mjs` 桩接上当假模型跑流程（具体接线见 docs/25 §7）——能验证链路，不能验证模型效果。

## 6. 常见坑速查（都是踩过的）

| 症状 | 原因 | 解法 |
|---|---|---|
| 打包卡在下载 Electron 不动 | 忘带 MIRROR 环境变量 | 用第 4 节带双镜像的完整命令 |
| 浏览器模式（start-zqq.bat）起不来：`listen EACCES: permission denied 127.0.0.1:8787` | 8787 被 WinNAT 排除段圈住（Hyper-V/WSL 动态端口保留，重启后可能漂移；本机 2026-11-16 实测段 8702–8801） | 当日构建已自动回退随机端口（输出里有实际地址）；旧版应急：`set PORT=8890` 再跑，或管理员 `netsh int ipv4 add excludedportrange protocol=tcp startport=8787 numberofports=1` 把端口钉给自己；诊断 `netsh interface ipv4 show excludedportrange protocol=tcp` |
| 桌面端 AI 执行命令每次都 `exit code: 3221225794`（=0xC0000142）且无输出，浏览器模式一切正常 | 桌面端 server 宿主无控制台（GUI 子系统 Electron），受限令牌 pwsh 只能共享宿主控制台（docs/1 2026-11-16 实施记录） | 当日构建已修（宿主无控制台时自动补隐藏控制台）；升级即可 |
| `npm install` 后 electron 目录是空的 | postinstall 被安全策略拦，二进制没下载 | 手动补：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js` |
| 别的机器上 AI 执行命令报「无法启动 pwsh」 | 目标机没装 PowerShell 7（只有系统自带 5.x） | 装 PowerShell 7（GitHub Releases 的 LTS msi），装完重开程序 |
| exe 一闪就退、无任何输出（exit 3） | 测试隔离时只改了 USERPROFILE 或三件套目录没真实存在 | 隔离测试要同时设 USERPROFILE/APPDATA/LOCALAPPDATA 且三个目录都先 mkdir（正式双击运行不会遇到，这是自动化脚本才会踩的） |
| `npm test` 里 contract 哨兵红 | 改前端时碰了锁定的约定（如 index.html 超 500 行、app/ 视图模块缺文件、纯逻辑模块引了 DOM、视图模块顶层裸 let 超限） | 看报错里的中文说明，按 docs/26 §9 的不变量改，别硬压哨兵（F4 后视图代码全在 app/ 七模块，哨兵清单见 docs/26 头部 F4 实施记录④） |
| 新加的 `public/app/*.js` 页面 404 | web-static 是启动时枚举注册的 | 重启服务（改文件内容不用重启，新增文件要） |
| portable 双击没日志 | SFX 壳不透传 stdout，正常形态 | 排障用 `npm run desktop` 或 win-unpacked 版 |
| 开了「最小化到托盘」后：关窗看不到图标、再双击程序也没反应 | 图标在 Win11 溢出区（任务栏 ^ 折叠箭头里）；旧版本（2026-11-16 前）隐藏窗口 focus 不可见——**升级到当日后构建即已修**（双击会唤回窗口）；应急：任务管理器结束 ZQQ-harness.exe，或删 `~/.ZQQ-harness/desktop.json` 复位 | 长期用可在 Windows 设置→任务栏→其他系统托盘图标里把 ZQQ-harness 设为常显 |
| 想隔离环境跑桌面 GUI 冒烟，Electron 一闪即退（0x80000003） | 本机怪象：改 USERPROFILE/APPDATA + 用户脚本会让 Chromium 早期崩溃（裸 electron 同环境存活；与本仓库代码无关） | 桌面 GUI 冒烟直接用真实环境+影响面收口（不绑工作区、desktop.json 测完删）；纯服务端隔离冒烟不受影响 |
| PowerShell Select-String 查中文日志「明明有却说不存在」 | PS5 按非 UTF-8 读无 BOM 日志，中文匹配假阴性 | 日志断言一律 Git Bash grep；PS 只做结构性判断（端口/进程/退出码） |
| PowerShell 里跑 GB 写法的命令报「无法识别」 | 环境变量前缀语法不通用 | 按第 4 节 PS 版写法 |
| 装完/首跑被 SmartScreen 拦 | 安装包未签名（已知取舍） | 「更多信息」→「仍要运行」；介意就只发 Setup.exe 并提醒对方 |

## 7. 一句话流程

```
改代码 → npm test + smoke:sa4 全绿 → npx electron-builder --win（带双镜像）
      → dist/win-unpacked 直跑冒烟 → （要发布才做）真装 Setup.exe 过第 5 节清单
```
