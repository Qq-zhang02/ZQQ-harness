## 0. 需求拆解（用户原话）

> 1. 「子代理异常变动需要报告给协调者，例如暂停后空返回，要让协调者知道这个子代理停了，且要报告状态例如空回复，已归档。或者暂停时已经完成任务了，就要返回结果让协调者知道。总之如果子代理有返回结果就要报告，多个报告一块就按顺序接收处理，异常暂停也要报告状态。」
> 2. 「子代理详情界面仍然会跳转，不保持当前位置阅读。」

### 0.1 W1 排查结论（改动前的真实缺口）

协调者感知子代理状态的**唯一事实源是工具结果文本**（SSE 事件不进协调者历史）。逐态核对：

| 变动 | 改动前协调者是否得知 |
|---|---|
| 正常完成/失败/超时/空回复 | ✓ 工具结果 |
| 上下文 >50% 强制归档 | ✓ 工具结果（forceArchived 说明） |
| **UI/插话暂停** | ✗ **协调者无限阻塞在 agent_task(s)/followup 的 await 里，什么都不知道，永远等下去**（用户看到的就是「暂停后（协调者）空返回」） |
| 归档请求中止（执行/暂停中） | ✓ 工具结果「任务被归档请求中止」——**但可复用结果尾部仍附「已保留待命」提示＝误导协调者向已归档实例追加任务（真 bug）** |
| UI 归档空闲可复用子代理 | ✗ 协调者下次 followup 才发现 |
| 用户停止协调者轮 | ✓ 工具结果「子代理被用户中止」（入历史，下一轮可见） |

「暂停时已经完成任务了就要返回结果」＝暂停与完成的竞态：任务收尾是同步段（句柄转 idle/注销在前），pause 落在其后即空操作——**自然满足**，无需特殊处理（新测试显式锁定该语义）。

### 0.2 W2 排查结论（跳变的三个根源，前两个是主犯）

详情页（#drwBody）的滚动保持机制（rebuildKeepScroll）本已存在，但被三处破坏：

1. **上下文占比轮询的全量重渲染**（主犯）：`ensureCtxPoll` 每 2s 逐个查 `/api/subagent/context`，而 `elapsedMs` **每轮必变** → `changed=true` → `renderDrawer()` → 详情页拆掉重建（`renderSeq++`、`stopLivePoll`、`body.innerHTML=""`、异步重新拉取）——运行中 worker 存在时**每 2 秒闪一次空白**，阅读位置必丢。
2. **预清空的空白窗口**：`renderDrawerDetail` 先 `innerHTML=""` 再 `await fetch`——即使低频事件（paused/done/init/state）触发的重渲染，也有「旧内容消失→网络往返→新内容+滚动恢复」的空窗，滚动归零再跳回。
3. **尾部跟随折叠的高度骤缩**：时间线默认「最后一条 assistant 组展开、其余折叠」——新一轮到达后上一个最后组被折叠，总高度骤减，scrollTop 恢复值被浏览器钳到新高度内＝位置跳变（回看中被折叠的内容也直接消失）。

### 0.3 定案总表

| 项 | 定案 |
|---|---|
| W1 暂停先行返回 | `pause()`（UI ⏸ / pause_subagent / interim 均同路）立即把 `{paused:true}` 状态经 facing promise 返回给**阻塞中的** agent_task/agent_tasks/agent_followup 调用——协调者解除阻塞，状态报明确「这不是最终报告；恢复后结果自动送达」 |
| W1 延迟报告送达 | 被暂停任务的真实收尾结果（完成/失败/空回复/归档/超时/中止）经 `deliverToCoordinator` 送进**协调者收件箱**（复用 W2-L1 的 `rt.inbox`）——与用户运行中插话共队列 **FIFO 按完成顺序**逐条处理；协调者空闲时立即 `startTurn` 开轮消化，忙碌时轮末排空续上。报告与工具结果同格式（formatWorkerResult）+ 前缀「[子代理任务报告 · 自动送达]」+ 一次性子代理附「已自动归档」注记 |
| W1 并发语义 | facing 提前 resolve **不释放并发槽**：`rt.workers` 登记的是真实任务 promise（暂停挂起照旧占额度，与文档口径一致） |
| W1 归档状态修正 | pendingArchive 收尾 `res.archived="request"`——工具层输出「已按归档请求归档」说明，**不再误报「已保留待命」**；上下文强制归档补 `archived:"context"`（与 forceArchived 同文案，消费面统一） |
| W1 UI 归档通知 | 界面归档**空闲**可复用子代理（协调者不可见的异常变动）→ 收件箱送达「[子代理状态 · 自动送达] …已被用户归档…」；工具路径（archive_subagent）的返回文案本身已抵达协调者，不重复送（`applySubagentControl` 增 `via:"ui"\|"model"`，控制路由传 "ui"） |
| W2 轮询就地更新 | ctx 轮询结果**就地刷新**列表行 meta 与详情头部（`refreshRowMetaInPlace`），**绝不**整抽屉重渲染；全量重渲染只留给低频状态迁移事件（paused/done/idle/archived/task） |
| W2 去预清空 | 同一子代理的重渲染**不预清空**：旧内容保持到新数据就绪由 rebuildKeepScroll 一次性同步替换；换看别的子代理（`drawer.renderedDetail` 变化）/换会话才清空重开（贴底） |
| W2 展开态冻结 | 回看（未贴底）时 `makeTimeline(…, keepOpen)` 冻结既有块的展开集（新一轮到达不再折叠「上一个最后组」——高度只增不减，scrollTop 恢复才有意义）；贴底跟随维持「尾部推进」默认态 |

### 0.4 明确不做（边界）

- 不做非阻塞派发（agent_task 正常路径仍阻塞至完成；只对「暂停」这一外部干预先行返回——docs/9「阻塞式派发下结构性不可达」的边界仅对暂停态解除）。
- 暂停中的 followup 仍拒绝（文案更新为「先恢复，它完成当前任务回到待命后才能追加」）。
- 二次暂停不重复通知（facing promise 只认首个 resolve；协调者已知道它暂停）。
- 报告送达不做批合并（一条报告一轮；与 inbox 逐条开轮的既有语义一致）。
- 普通会话零改动（无 subagent 服务，deliverToCoordinator 不可达）。

## 1. 实施记录（2026-11-13 交付）

### 1.1 W1 后端（web/subagents.ts 为主战场）

1. **类型**：`SubagentResult` + `paused?: boolean`、`archived?: "request" | "context"`（core/types.ts）；`ActiveSubagent.requestArchive?(via?: "ui" | "model")`（core/host.ts）。
2. **facing 通道**：新 `TaskFacing` / `makeFacing()` / `settleTask(sh, rt, p, name, facing)`——服务层（`subagentServiceFor.run` / `followup`）把真实任务 promise 包装成 facing.promise 给调用方：pause 时 `reportPause` 先行 resolve（detached=true），任务定型时未暂停则原样透传、已暂停则 `deliverToCoordinator(reportMessage(res, name))`；拒绝路径兜底（facing 不悬挂）。`runWorker`/`startWorker`/`runOneTask` opts 增 `facing`，挂在 `ws.facing`（装配窗口即生效；followup 每任务重挂；收尾清除）。
3. **pause()**：广播 paused 事件后 `ws.facing?.(pausedResultOf(...))`——状态报带 subId/name/已发生用量/用时/实时上下文占用（有值才带）。**竞态天然正确**：收尾同步段先转 idle/注销句柄，pause 落在其后即空操作（返回真实结果）。
4. **deliverToCoordinator**：`(rt.inbox ??= []).push(text)`；空闲（`!rt.busy` 且 runtime 未被替换且有工作区）时经 `sh.ctx.sessionHost.startTurn(rt, inbox.shift())` 立即开轮（web-sessions /api/chat 同款模式；不经 import 直连 session-lifecycle——那会成环 runtime↔lifecycle）。测试直调场景无 sessionHost → 只入队（断言 inbox）。
5. **reportMessage**：`[子代理任务报告 · 自动送达]\n` + `formatWorkerResult(...)` + 一次性尾部「（该子代理为一次性：任务结束已自动归档。）」——**web 壳 import modules/tools/agent-task**（server.ts 引 sandbox 模块先例，方向合法且无环）。

### 1.6 已知边界（诚实声明）

1. 暂停先行返回只在**任务 promise 未定型**时抢先（竞态窗口=收尾同步段，JS 单线程下 pause 不可插入——语义 guaranteed，非概率）。
2. 报告送达依赖协调者会话在内存（服务重启丢 inbox——与 W2-L1 用户排队同语义）；`deliverToCoordinator` 对 runtime 已替换的会话静默跳过开轮（消息仍在 inbox 随会话消亡）。
3. 展开态冻结只在**未贴底**时生效；贴底跟随下 done 转换仍会折叠旧组（设计意图：跟随者要的是尾部可读，历史可回看时再冻结）。
4. 「[子代理状态 · 自动送达]」（UI 空闲归档）与报告同为用户消息开轮——每条至少一次 LLM 调用（用户明确要求协调者知情，成本知情）。
5. web → modules/tools/agent-task 的新 import（formatWorkerResult 复用）——模块间禁止互 import 的哨兵不受影响（哨兵只扫 src/modules/**；方向=壳引模块，server.ts 先例）。
