# 36 · 交接文档——首轮装配进度可视化（系统提示词 / AGENTS.md / 技能 / MCP 注入亮牌）

> 状态：**已实施**（2026-11-18，随本轮收尾；typecheck 三段过 + npm test 514/514 全绿 + smoke:sa4 11/11）。
> 来源：用户追评——第一次对话开始时希望看到系统提示词注入的情况（系统提示词+全局/工作区提示词+技能列表+MCP 注入），这些完毕后才把用户请求发过去；展示顺序按真实装配时序自行安排。

## 需求与语义

- **痛点**：会话第一条消息发出后，若 MCP 握手慢（冷启动型服务器可达 20s+），界面只显示"运行中"
  没有任何中间反馈，像卡死；装配到底做了什么、请求什么时候才真的发出去，用户完全看不见。
- **既有事实**（本条只是把它**可视化**，顺序本来就有保证）：startTurn 同步段完成技能重扫+两级
  AGENTS.md 重读+系统提示重建 → 异步段 `await rt.mcpReady`（MCP 闸门）→ 压力检查/自动压缩 →
  `agent.run` 发请求。**请求永远在装配完成之后才发出**。
- **展示顺序 = 真实装配时序**（用户明确允许自行安排）：
  1. `🧩 系统提示装配完成：系统提示词 615（基础规则+两级 AGENTS.md）· 系统工具 2.4k · 技能 N 项（x.xk） tokens`
     ——同步段完成后立即广播（数字来自 `contextEstimate().breakdown`，与顶栏 token 面板同源）。
  2. `🔌 MCP 注入：已连接 a、b；未连上：c（原因）——服务器使用说明已并入系统提示，mcp__ 工具可用`
     ——`mcpReady` 收口后广播；**无任何 MCP 配置时整行省略**。协调者会话走「子代理 MCP 注入」口径
     （说明进「子代理系统提示词说明」段、协调者自身不带 mcp__ 工具——文案如实区分）。
  3. `✅ 装配完毕，用户请求已发出`——紧贴 `agent.run` 之前广播（若触发自动压缩，压缩提示行天然插在
     ②③ 之间——同样是"请求发出前"的真实时序）。
- **触发面**：每个**运行实例**的第一条消息（`rt.assemblyShown` 瞬态标志，core/host.ts SessionRuntime
  新增可选字段，不入档）。新建会话、以及**重启/恢复档后的首条消息**都会展示（后者正是 MCP 重连等待
  最需要可见性的窗口）；后续消息零广播。
- **通道复用**：SSE `info` 事件 → 前端 sysLine 渲染（零前端改动、零新事件名——契约测试的 13 事件名
  不变）。运行中插话/后台会话经既有 route 缓冲，切回重放同路径。

## 实现（两文件 + 测试）

| 文件 | 改动 |
|---|---|
| `src/core/host.ts` | SessionRuntime 增瞬态可选字段 `assemblyShown?: boolean`（注释说明展示语义与重启复位） |
| `src/web/session-lifecycle.ts` | startTurn：同步段后广播 ①；异步段 mcpReady 后广播 ②（按 kind 分口径）；压缩检查之后、`agent.run` 之前广播 ③；`kTok` 本地格式化（与前端 fmtTok 同口径） |

## 验证

- 单测 `session-runtime.test.ts` 2 项（22/22）：普通会话首条消息三段按序广播（stub MCP 服务器
  「已连接 demo」）且第二条零广播；无 MCP 配置省略 ②；协调者走「子代理 MCP 注入」口径、收尾仍是 ③。
- 浏览器实测（隔离 USERPROFILE 实例 + 协调者会话）：首条消息依次渲染 ①→③（该配置无 MCP，②正确
  省略），请求在 ③ 之后才发（桩端点连接错误出现在 ③ 之后）；第二条消息零装配行。
