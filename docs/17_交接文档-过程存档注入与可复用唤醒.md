## 0. 需求拆解（用户原话）

> ① 归档/失效指引说「任务书可让它先读过程存档 📄 过程 接续上下文」，但实际上子代理读不到过程存档——做一个**存档注入工具**：不要直接读 json，类似于给模型发送信息，把 json 转为可读的信息，不要多余的语法格式。
> ② 子代理记录文件和对话记录文件的格式不太一样——把子代理的改为主对话的那种，这样**退出后复用子代理也能继续复用**，存档注入工具也能兼容两种对话记录。

### 0.1 问题定位（为什么「读过程存档」此前不可达）

1. `[[过程档案#N]]` 只是**前端 UI 链接标记**（index.html linkify → 抽屉详情页 → `GET /api/subagent-transcript` HTTP 接口）——模型拿不到任何文件路径，`read_file` 无处下手；
2. 即使知道路径（`~/.ZQQ-harness/spill/<sessionId>/sub-N-name/transcript.json`），它也是**原始大 JSON**（`{messages: ChatMessage[]}` 裸对象）——直接读进上下文全是转义与语法噪音，与「给模型发信息」背道而驰；
3. 子代理存档格式（裸 `{messages}`）与主对话档（`SessionData`：元数据 + messages）不一致——主对话靠该格式实现重启恢复（`createRuntime` → `Agent.restore`），子代理从不回读，所以可复用实例重启即死（docs/9 的「用户定案：不跨服务重启存活」）。

### 0.2 定案总表

| 项 | 定案 |
|---|---|

### 0.3 明确不做（边界）

- 不做派发时宿主自动注入（用户选型确认跳过）；不做 read_archive 的协调者注册（防转述搬运撑爆协调者上下文——协调者要了解存档内容就派一个「读存档并汇报」的 worker）。
- 不做跨会话的 subId 寻址（subId 只在本会话记录里解析——跨会话接续用 sessionId 读主对话档，或重派后让新 worker 自己 read_archive）。
- 已归档子代理**不可唤醒**（归档语义不变）：接续 = agent_task 重派 + read_archive。
- 不做一次性子代理的唤醒（记录 state=archived，与归档同闸）；不做存档的写放大（仍是每任务收尾累积重写单文件）。
- 唤醒后 usageAnchor 置空（Agent.restore 既有行为）→ 上下文估算回退本地估算直至下次请求重建锚点；记录里的 contextPct 照旧携带（门槛不失守）。

## 2. 已知边界（诚实声明）

1. **唤醒的上下文延续是有代价的**：唤醒后的第一条请求即携带全量历史（存档时刻的全部 messages）——记录 contextPct ≥35% 时闸门先行拒绝（不读档不唤醒），唤醒后若任务把占用推过 50% 会在收尾强制归档（治理三档照常工作）。
2. **存档缺失/损坏不可唤醒**（降级为重派指引）：transcript 是 best-effort 落盘（写失败记录不带入口）；会话删除连带清理 spill（cleanSpill）——删过会话的记录自然失去唤醒资格。
3. **旧格式存档可注入、不可带 meta 唤醒参差**：裸 `{messages}` 档唤醒时 effort/scope/system 继承会话缺省（角色段丢失）——旧档用户如需精确保真，重派 + read_archive 接续。
4. **read_archive 读的是任务边界快照**：对运行中/暂停中的 worker，transcript 落后于内存活历史（每任务收尾重写）；工具结果头部说明行已注明「快照截至最近一次任务结束」。活历史出口仍是抽屉详情页（liveMessages 轮询）。
5. **渲染预算是一次性头部截断**（80k 字符，head-only）：超长存档的尾部不进入首次注入——需要尾部内容时让 worker 再调一次（存档全文在盘上，未来可加 offset 参数；当前按「缺什么再读什么」的模型自主性处理）。
6. **subId 跨会话不可寻址**：read_archive 的 subId 只解析本会话记录（接缝按 rt 闭包）；跨会话接续走 sessionId（主对话档）。
7. **唤醒不广播 spawned**：抽屉行已存在（记录驱动），随后的 task 事件起跑翻行——若协调者会话在唤醒装配窗口（毫秒级）被强制刷新，行短暂显示休眠态属预期。
8. seq 续期规则不变（从记录最大 subId+1）：唤醒**不占新号**（同 subId upsert），subagentTotal 配额不因唤醒增长（与 followup 同口径）。
