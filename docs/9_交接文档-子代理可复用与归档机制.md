## 0. 需求与语义定案（用户原话拆解）

> 「我需要把子代理分为可重复利用的与简单一次性任务的子代理，可重复利用的子代理完成或者被暂停后，可继续由协调者向其发起任务请求，若不再使用该子代理则将其归档。一次性子代理使用一次就归档。归档后仅可查看，不可再次向其发起请求。」

**已与用户确认的决策**：可复用子代理**不跨服务重启存活**（推荐项）——重启后其待命记录与全程 transcript 保留为只读（界面标「服务重启后失效」），协调者再派时会收到明确引导文案。

### 0.1 状态机（实现定案）

```
一次性（缺省，与历史版本行为一致）：
  spawned ─▶ run ⇄ paused ─▶ done/error（=已归档，记录 state:"archived"）

可复用（agent_task 带 reusable:true）：
  spawned(reusable) ─▶ run ⇄ paused ─▶ idle（待命：SSE phase "idle"，记录 upsert state:"idle"）
          idle ─▶ run（agent_followup 派新任务，phase "task" 起跑）─▶ idle …
          idle / paused / run ─▶ archived（phase "archived"：idle 立即归档；执行/暂停中=中止当前任务后于收尾归档）
```

关键语义：

1. **历史延续 = 复用价值**：可复用 worker 的 Agent 实例与完整历史跨任务驻留，`agent_followup` 的新任务作为新 user 消息接在既有历史上（任务书可引用之前的进展）；`scope`/`effort`/`system` 等 Agent 构造期参数沿用首次派发，followup 不可改。
2. **归档三态入口**：idle → 立即归档；执行/暂停中 → 置 pendingArchive + 中止当前任务信号 + 闸门放行，任务收尾时归档（失败归因「任务被归档请求中止」）；装配窗口（句柄已注册、Agent 未就绪）→ archiveRequested 标记，装配完成后不执行任务直接归档。归档后句柄注销、记录定格 `state:"archived"`，transcript 只读——followup/pause/resume 全部拒绝。
3. **一次性 = 现状 + 明确归档语义**：done/error 即自动归档（记录带 `state:"archived"`，事件流与结果拼装与历史版本字节级一致）。
4. **配额**：可复用 spawn 计一次 `subagentTotal`（与一次性同）；followup 不计累计但检查并发上限（`rt.workers.size`）与**每实例任务数上限 `subagentMaxTasks`（新阈值，默认 12，harness.json 可覆盖）**。
5. **协调者感知存活状态的唯一事实源是工具结果文本**（SSE 事件不进协调者历史）：可复用结果尾部追加待命提示「（该子代理可复用：name#subId 已保留待命，后续任务用 agent_followup …；不再使用时用 archive_subagent 归档。）」，followup 结果 stats 带「第 N 次任务」。

### 0.2 新工具与参数（协调者 registry 四件 → 六件）

| 工具 | schema 要点 | 行为 |
|---|---|---|
| `agent_task`（改） | 任务项增 `reusable?: boolean`（默认 false） | reusable=true 派出可复用 worker；首任务照常阻塞返回 |
| `agent_tasks`（改） | 批内任务项同样支持 `reusable` | 透传即可（parseTaskItem 共享校验） |
| `agent_followup`（新） | `subId`/`name` 二选一 + `task`（必填）+ `description`/`timeoutMs` | 向**空闲待命**的可复用子代理追加任务；各拒绝态（不存在/已归档/重启失效/同名歧义/执行中/已暂停/超任务上限）各有明确文案；阻塞到完成 |
| `archive_subagent`（新） | `subId`/`name` 二选一 | 归档可复用子代理（见状态机）；一次性子代理返回「任务结束即自动归档，无需手动归档」 |

**明确边界（阻塞式派发下结构性不可达的态）**：协调者在 worker 运行期间阻塞在工具 await 里，无法调用任何工具——「运行中收到 followup」对各模型不可达（服务端仍防御性拒绝并给指引文案）；「暂停后直接派后续任务」同理（须先恢复并等当前任务结束）。非阻塞派发是将来独立议题（docs/5 预留的接缝）。

### 1.3 关键选型

- **驻留注册表的位置**：reusables Map 放在 `subagentServiceFor` 服务闭包（会话同生命周期），不放 SessionRuntime——followup 寻址/归档释放只有服务自身消费；UI/控制面经 `ActiveSubagent` 句柄（requestArchive/status/summary/tasks）与 `rt.activeSubagents` 即可，不触碰 SessionRuntime 结构。runWorker 直调（单测）不传时用局部 Map：归档仍可用，仅 followup 不可寻址。
- **审批闭包 per-task 重建**：原 runWorker 一次性闭包捕获单一 sig；多任务下任务 2 的中止信号必须挂对任务 2 的审批链（否则中止后审批卡悬挂——P1 死锁回归）。实现为 `ws.approval` 可变引用，workerDeps.requestApproval 闭包读当前值。
- **记录 upsert（而非 append）**：可复用 worker 每任务结束更新同一条记录——`subagentTotal` 恢复口径（条数）不被 followup 灌水、`[[过程档案#N]]` 链接稳定、重启后 idle 记录可见（只读失效展示）。附带修复：**seq 续期**（惰性取记录最大 subId，防撞号）。
- **idle 事件载荷与记录同口径（累计）**：真机首验发现事件发单任务统计、state 快照回填累计统计 → 行显示在两口径间闪烁；统一为累计（单任务统计仍在工具结果文本「第 N 次任务 · M 轮」里给协调者看）。
- **装配窗口归档**：真机首验暴露的**真 bug**——句柄注册先于 Agent 装配（中间有 MCP 懒加载 await），该窗口收到归档会「立即归档」但首任务照跑（句柄已注销、任务收尾再 upsert idle 记录=脏状态）。修复：`archiveRequested` 标记 + 装配完成后直接归档收尾（不执行任务，结果「任务未开始：派发后即被归档」）。
- **followup 仅 idle 受理**：阻塞式派发下 run/paused 态对模型结构性不可达（协调者阻塞在工具 await），防御性拒绝并给指引文案；不做任务排队（非阻塞派发是将来的独立议题）。
- **暂停/执行中归档 = 中止后归档**（用户便利语义）：ctl.abort + 闸门放行 + pendingArchive 标记，收尾走归档分支；失败归因独立文案。

### 1.5 过程缺陷（诚实记录）

1. **真 bug（应用层，已修）**：装配窗口归档竞态（§1.3）——首验时归档落在句柄已注册但 Agent 未装配的窗口，立即归档后首任务照跑。修复：archiveRequested 标记 + 装配完成后归档收尾；单测「首轮边界归档」与「暂停中归档」覆盖相邻窗口。
2. **口径不一致（应用层，已修）**：idle 事件发单任务统计、记录 upsert 发累计 → 行显示被 state 同步覆盖闪烁（§1.3）。统一累计。
3. **桩缺陷三件（应用无涉，真机首跑当场抓获）**：①reuse 桩 sseBody 丢了 `toolName = "write_file"` 默认参数且 worker 分支未传 → 工具名 undefined 被应用过滤成「空回复」（worker 首轮即失败）；②桩的 `hasTool` 全文扫描——多轮历史里旧 tool 消息常驻，第二轮 goal 的派发轮被误判成总结轮直接编结论文案（跳过 agent_followup）；③手写隔离 providers.json 缺 `format` 字段被校验拒绝（回退默认 deepseek 配置）。三者修复后全链路干净复现。
4. **测试桩缺陷（已修）**：两处自定义挂起 provider 缺「信号先于请求到达」预检（中止落在装配窗口时 chat 收到 pre-aborted 信号、abort listener 永不触发 → 测试挂死）；对齐库内既有 abortable 桩写法。

### 1.6 已知边界（诚实声明）

1. **可复用子代理不跨服务重启存活**（用户定案）——重启后待命记录只读失效展示；协调者 followup 得到「不在线」引导（可让新 worker 先读旧过程存档接续上下文）。
2. followup 仅空闲态受理；执行/暂停中防御性拒绝（阻塞式派发下该态对模型不可达）；批量并行 followup 不做（阻塞式工具天然串行）。
3. `scope`/`effort`/`system` 固定于首次派发（Agent 构造期），followup 仅可指定 task/description/timeoutMs。
4. idle 行的轮数/用量为**全部任务累计**（单任务统计在工具结果文本里）；记录 `ok/error` 为最近一次任务结果。
5. 归档时若该 worker 正在执行任务：当前任务以「任务被归档请求中止」失败收尾（其部分过程已入 transcript）。
6. 可复用 worker 每任务结束累积重写同一 transcript.json（无按任务分段存档）；会话删除连带清理不变。
