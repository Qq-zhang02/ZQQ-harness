## 1. 阅读链路全景（截断在哪一层生效）

一次"读大文件"任务要过的所有阈值关卡（自上而下 = 任务发生顺序）：

```
选目标文件 ──→ textFileMaxBytes（5MB）硬拒：文件三工具不碰超 5MB 的文件，报错文案指路 run_pwsh
     │            消费点 file-tools.readTextFile(maxBytes = THRESHOLDS.textFileMaxBytes)
     ▼
read_file 调用 ──→ readFileDefaultLines（4000 行）缺省读取行数；offset/limit 参数分页续读
     │            消费点 read-file.ts（THRESHOLDS.readFileDefaultLines）
     ▼
单次自限 ──→ min(readFileMaxChars 200k, readToolResultMaxChars 120k) 字符截断
     │        【docs/40 单层化】截断发生在 read_file 内部：头部"显示第 X–Y 行"与模型实见一致，
     │        "用 offset=N 续读"提示保留；注册表修剪退为兜底（正常不再触发）
     ▼
注册表修剪 ──→ 预算解析：tool.resultBudget() 声明（阅读类 120k）> ctx 传入 > toolResultMaxChars（48k）
     │         超预算只留头部 + 省略标记；spill 目录在场时【触发即全文落盘】
     ▼
spill 落盘 ──→ ~/.ZQQ-harness/spill/<会话>/<n>.txt，入模型文本附检索提示
     │         （模型可用 Get-Content/Select-String 按需读取；spillMaxAgeHours=168h 启动清扫）
     ▼
会话累计 ──→ compactionPressure（0.8）× contextLength（提供方配置，缺省 1M token）
     │        占用达线 → 自动压缩；溢出 400 → 兜底压缩重试一次
     ▼
摘要生成 ──→ compactionSummaryMaxChars（300k）防超长：头+尾保留（尾 10%≈30k，docs/40 修正）
     │        保留工作集 = compactionKeepRatio（0.3）× 窗口的尾部完整轮次；备份 precompactKeep（3）份
     ▼
委托阅读 ──→ 子代理报告 subagentResultMaxChars（32k）修剪 + spill；
             可复用子代理上下文三档：warn 25% / followup 拒收 35% / 强制归档 50%
     ▼
轮次上限 ──→ maxToolRounds（15；本机 harness.json 30）达限强制收尾总结——单轮能读多少次的上界
```

**token 口径**（字符预算换算用）：项目内置 DeepSeek v4 tokenizer 做真实计数（UI 层），缺省回退比例 1 中文字符 ≈ 0.6 token、1 英文字符 ≈ 0.3 token（`tokens.ts estTokensHeuristic`，未来 token 语义预算的现成地基）。即：阅读类单次预算 120k 字符 ≈ 中文 7.2 万 token / 英文 3.6 万 token。

**对大量阅读任务的实操结论**：单次 read_file 实际可读 120k 字符（自限即注册表口径）；超过的部分靠 offset 续读或 pwsh 定向检索；被剪的 pwsh/MCP 大输出全文在 spill 里（7 天内有效，重要内容及时拷走）；会话上下文 80% 触发压缩时，**摘要输入保头保尾、中段丢弃**——阅读密集会话的重要中间结论应在压缩前落到工作区文件。

## 3. 问题清单（分级标准引 docs/21 §2.1）

| 级 | 问题 | 根因与实例 | 处置（§4/§5） |
|---|---|---|---|
| P1 | **双层截断失真** | read_file 内部上限 200k（`READ_FILE_MAX_CHARS`）≠ 注册表预算 48k（`toolResultMaxChars` 全局）——模型被告知"显示第 1–4000 行"但实见 ~48k 字符；read_archive 更是 160k 预剪后注册表再砍，spill 落的还是已剪版 | 单层化：工具自限 `min(内部上限, 自己预算)`，注册表兜底；read_archive 不再无谓 spill（存档本体已在盘上） |
| P1 | **全局预算不分工具** | 阅读类（read_file/read_archive/load_skill）与 pwsh/MCP 共用 48k——大文档单次可读量被锁死，续读轮次暴涨 | 新键 `readToolResultMaxChars` 120k + `Tool.resultBudget` 挂钩（声明 > ctx > 全局） |
| P1 | **摘要输入 head-only 丢最新上下文** | docs/10 R2 的 head-only 依据（尾部=日志残余）只对工具输出成立；压缩摘要输入的尾部=最近上下文，阅读密集会话压缩即丢中后段 | `pruneToolResult` 增 `tailChars`；摘要输入尾留 10%；docs/10 追记勘误（原文保留） |
| P2 | **export let live binding 纪律脆弱** | 30+ 可变常量靠"导入期不得消费"纪律；真实实例：agent-task `TASK_ITEM_PROPERTIES` 顶层对象把 `SUBAGENT_TIMEOUT_MIN_MS` 缺省 60000 冻结进 schema minimum（运行时校验活、对外 schema 死，两处不一致） | THRESHOLDS 单对象 + 原地 Object.assign（身份恒定，捕获引用也见新值）；agent-task 改惰性 `taskItemProperties()`（mcp-manage 先例）；哨兵禁顶层解构 |
| P2 | **文档漂移** | README 写"三十四个运行阈值"，实际 35 活跃（缺数批次累加没人对总账） | `threshold-docs.test.ts` 逐键校验 README 覆盖 schema 全部活跃键 + 总数口径哨兵 |
| P3 | **修剪不可观测** | prunedChars 只在单次 UI 元数据，会话累计无处可看——调参凭感觉 | Agent.pruneStats（次数/字符/spill 份数）→ state 载荷 → Token 面板一行 |
| P3 | **字符 ≠ token** | 48k/120k 字符预算在中文/英文间 token 差 2 倍 | 本轮不改预算单位（换算口径写进 §1）；`estTokensHeuristic` 留作未来 token 语义预算地基 |
| P3 | **子代理报告 16k 偏小** | 委托阅读的回报瓶颈；键不在提示词插值，改缺省 golden 零影响 | 缺省 16k→32k（三态断言同步；用户 harness.json 同步 32k） |

**明确不做（边界）**：不做嵌套 per-tool 覆盖映射（破坏扁平数值键的校验/前端 schema 架构，收益不成比例）；不做按剩余上下文的动态预算（复杂度高，静态预算 + 80% 压缩线已覆盖）；不把预算单位改成 token（字符口径直观、estTokens 有误差；文档化换算即可）；不推翻 docs/10 R2 工具输出 head-only（其依据对工具输出仍然成立——只修正摘要输入这一个语义不同的消费方）。

## 4. 阶段二：阅读链路修复（已实施）

1. **新键 `readToolResultMaxChars`（三件套）**：`EffectiveThresholds` 字段 + `THRESHOLD_RULES` 行（group=general，range 整数 >0）+ `resolveThresholds` 缺省 120_000；config.test 三态 + contract schema 计数 35→36；前端 ⚙ 面板 schema 驱动零改动自动出现；README 示例与说明段同步。
2. **`Tool.resultBudget?(ctx): number` 挂钩**（registry.ts，executeImage 先例）：修剪预算解析 `tool.resultBudget?.(ctx) ?? ctx.toolResultMaxChars ?? THRESHOLDS.toolResultMaxChars`；实现纪律 = 调用期求值（闭包直读 THRESHOLDS，不得工厂导入期捕获）。registry.test 锁定优先级。
3. **read_file 单层化**：内部自限 `min(THRESHOLDS.readFileMaxChars, THRESHOLDS.readToolResultMaxChars)`——注册表修剪不再触发，头部行区间准确、offset 续读提示保留；`resultBudget` 声明阅读类预算保证兜底口径一致。
4. **read_archive 单层化**：自限 `min(THRESHOLDS.archiveRenderMaxChars, THRESHOLDS.readToolResultMaxChars)`；不 spill（docs/17：存档全文本就在盘上，缺什么再读什么——修掉"160k 预剪又被注册表再砍、spill 落已剪版"的缺陷）。
5. **load_skill 挂钩**：`resultBudget` 声明阅读类预算；超出仍由注册表统一截断 + spill（SKILL.md 超大是异常态，spill 全文合理）。
6. **prune 头+尾模式**：`pruneToolResult(text, budget, spill?, opts?: { tailChars })`——尾部 capped 预算 1/4、两切点独立 codePointBoundary、spill 行为不变；缺省不传 = 纯 head-only，**工具输出路径零改动**。session-runtime summarize 改用 `{ tailChars: 预算×10% }`。
