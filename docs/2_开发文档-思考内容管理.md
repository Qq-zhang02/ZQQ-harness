> **现状核实日期**：2026-09-23。本文 §0 的每条断言均已在当日对照源码文件确认。

## ⭐ 实施记录（2026-09-23，M1–M5 全部落地）

设计已全部实现：`npm run typecheck` 通过；`npm test` 146 项全绿（原 121 + 新增 25：anthropic 回放矩阵与 SSE 捕获 7、openai 回传矩阵 7、agent 存储/降级/计数对齐 5、tokens 双口径 2、config 开关 2、sessions 存档往返 1，另修 1 处既有断言）。§0 保留为实现前基线，以下为与设计的差异（**以代码为准**）：

- **当前模型名透传**：`LLMProvider` 接口新增可选 `readonly model` 字段（两个 provider 原有字段转公开），agent 直接读 `provider.model`——不走 AgentDeps 回调，少一处接线；测试桩可不提供（此时存的思考无 model 字段，回放层自然视为不对齐）。
- **降级告警通道**：`ChatParams` 新增 `onReplayDegrade(reason, source)`；agent 注入回调（`ui.printInfo`）并用 `WeakSet<ThinkingBlock>` 去重——同一思考块在多轮工具循环中反复发送只告警一次（设计只说"告警一次"，实现明确了去重键=思考块对象）。
- **回放门槛**：anthropic 路线**仅在思考开启的请求回放 thinking 块**（effort low/high/max 即 budget 存在时；off/default 请求保持纯净历史）——设计未明说，但思考关闭却回传 thinking 块对官方端点同样是不一致输入；该门槛与 token 计数判定共用 `isThinkingEffort`。
- **openai 回传条件**：`REASONING_PASSBACK 开关 && isThinkingEffort(effort)`。设计的"仅在 effort≠default"被收紧为**不含 off**（off 是显式关闭思考，不属于 DSH 所说 "required in thinking mode" 的思考模式）；`REASONING_PASSBACK` 按 env 读取的函数（config.ts，识别 1/on/true/yes），非常量。
- **计数对齐**：`estimateBreakdown` 增加第 5 参逐消息谓词 `thinkingPassback`；`messageTokens` 缓存升级为 `{plain, passback}` 双口径（同一消息在开关/档位变化前后两种口径都缓存，WeakMap 按对象身份），`compact()` 的切点估算同步用 passback 口径。
- **签名细节**：捕获时 `reasoningSignature` 仅在非空时携带（没收到 signature_delta = 字段缺省）；存档中 `signature: ""`（空串）是合法值且回放逐字透传（DSH serialize 同款），字段缺省才走降级。
- **M4**：`server.ts` 压缩摘要调用 `effort: "default"` → `"off"`（openai 路线显式 `thinking:disabled`）；本项目无 session-title 类辅助调用，唯一辅助调用点即压缩。
- **UI**：思考流展示不变（§2.6）；未加 /status 回传计数行。

**验收状态**：M1/M3/M4/M5 验收标准全部达成（含"默认 off 行为与现状逐字节一致"矩阵单测）。M2 真实冒烟已于同日补齐（见下）。

## ⭐ 追加实施（2026-09-23 同日晚：思考显示 + M2 真机验收）

用户需求「我需要显示思考」+ 已配置 anthropic 格式提供方（deepseek-anthropic：DeepSeek 官方 Anthropic 兼容端点），引出两处变更：

- **最终回答轮也存思考（推翻本文 §2.1"不做"中的"存最终回答轮次的思考"）**：不存就无法在切换会话/刷新后显示最后一轮思考。API 侧零影响——回放与回传范围**明确限定在带 toolCalls 的轮次**（`toAnthropicMessages` 加 `m.toolCalls.length > 0` 门槛；openai 路线原本就限定）；anthropic 计数谓词同步加该门槛，计数==回放不漂移。存档体积换显示完整性，用户知情选择。
- **前端历史渲染**：`renderHistory` 对带 `thinking` 的助手消息渲染折叠思考块（复用 `.think/.collapsed` 样式，标题带字数，点击展开），工具轮与最终轮都显示；与"切换补放"机制正交（在途 delta 重放生成 live 框，已落历史的走快照渲染）。**端到端已验证**（真机 DeepSeek effort=high 工具轮）：运行中两条思考块折叠（工具轮 725 字 + 最终轮 89 字）→ 刷新页面折叠重现 → 点击头部展开 → 切走再切回不丢。

**M2 真机验收（最强验收项，`npm run smoke:anthropic`，脚本 scripts/smoke-anthropic.ts）**：DeepSeek anthropic 端点 + effort=high + 多轮工具循环通过——思考流 289 字、存档 2 条思考块（工具轮+最终轮，均含签名）、按当前模型构造回放恰好 1 个 thinking 块（工具轮；最终轮正确排除）、第二轮带签名回放无 400、降级告警 0。**端点实测发现**：①DeepSeek 的 signature_delta 签名=本条消息的 UUID（占位签名），逐字回放被端点接受；②思考是自适应的——简单任务（Get-Location）带 tools 也不思考，冒烟任务必须带推理成分才能触发思考块；③诊断探针 scripts/probe-anthropic-sse.ts 可直连端点统计 SSE 事件类型（排障用）。

## 0. 现状基线（全部经文件实证）

### 0.1 思考内容的数据通路（现状）

```
API 流（openai: delta.reasoning_content ／ anthropic: thinking_delta）
  → provider 聚合进 ChatResult.reasoning（provider.ts:57 "仅展示用，不回传 API"）
```

### 0.3 两个已知风险项（本项目的动机）

1. **Anthropic 官方端点的 400 风险（确定性问题）**：Anthropic Messages API 在扩展思考开启时，要求 tool_use 轮的 assistant 消息携带带有效签名的 thinking 块。我们既不存 thinking 也不存签名，用官方端点 + effort≠off + 多轮工具调用**预期必现 400**。目前靠"头注释自认限制"扛着，没用官方端点跑过工具循环就还没炸。
2. **DeepSeek V4.1 文档矛盾（未复现）**：官方文档称带 tools 的请求必须回传之前所有轮次 reasoning_content 否则 400；我们从不回传，实测（smoke + 日常）无 400。已列待核查风险项。

## 1. DSH 参照设计（调研结论）

### 1.1 条件回传规则（Chat Completions 路线）

`packages/llm/llm-deepseek/README.md` 原文：

> **Reasoning passback rule**: on assistant turns that carried tool calls, `reasoning_content` is serialized back in history (**required by the API in thinking mode**); on tool-call-free turns it is **dropped** (ignored anyway — saves tokens).

即：**带工具调用的助手轮次回传**（thinking 模式下 API 要求）；**最终回答轮次丢弃**（API 反正忽略，省 token）。文档并算账：条件回传会在工具轮询期间增大上下文、影响 KV cache 前缀；丢最终轮思考避免重复付费。

### 1.2 思考内容入会话日志

模型响应中 "Reasoning, text, and raw-string tool arguments are translated into harness chunks **for the loop to log and assemble**"，且 "only loop-retained blocks affect later input"——思考是日志的一部分，被循环保留的块参与后续请求（不是纯展示流）。

### 1.3 Messages 路线：原生 thinking 块 + ReplayEnvelope（2026-09-07 决策，2026-09-19 起为唯一官方路线）

- Messages 协议把 thinking、签名、工具调用作为**原生协议字段**；"Assistant blocks remain the durable model-visible content"。
- 版本化 **`ReplayEnvelope`** 只存回放元数据：协议格式、模型身份、对齐的块类型、签名。**同模型续会话签名逐字还原（包括空签名）；跨模型历史不伪造签名**；元数据不可用时按降级规则省略并告警。
- 明确否决两个替代方案：持久化完整原生响应（与日志重复）；**把 thinking 压平成正文**（"Flattening changes the next model input"——会改变下一次模型输入）。

### 1.4 辅助调用强制关思考

session-title 生成强制 thinking disabled；压缩调用走独立标记（请求头 `x-deepseek-harness-compact: 1`）的独立调用——辅助调用不付思考成本、思考输出也不污染主会话。

## 2. 设计方案（本项目）

### 2.1 目标与明确不做的事

**目标**（按优先级）：
1. Anthropic 路线：thinking 块 + 签名的存储与回放（消除 §0.3-1 的确定性 400）；
2. 辅助调用关思考（配合主文档 M3 压缩）；
3. DeepSeek 路线：条件回传做成**零成本开关**（默认关，撞 400 时打开即合规）；
4. token 计数覆盖回传的思考内容（守住六类和 = promptTokens 不变量）。

**不做**：全量回传所有轮次思考；把思考并入正文/压平；思考进前端历史导出（仍纯展示）；存最终回答轮次的思考（体积大且无用）。

### 2.2 数据模型（最小侵入）

```ts
// provider.ts
export interface ThinkingBlock {
  text: string;
  signature?: string;   // Anthropic 有效签名；openai 路线无此概念
  model?: string;       // 产出该思考的模型（回放对齐判定用，见 2.4）
}
export type ChatMessage =
  | ...
  // 仅在【带 toolCalls 的助手消息】上存在（与 DSH 条件规则一致，兼控存档体积）
  | { role: "assistant"; content: string | null; toolCalls: ToolCallRequest[]; thinking?: ThinkingBlock }
  | ...;

// ChatResult 增加：
reasoningSignature?: string;   // anthropic 路线捕获的签名
```

- **存储条件**：`result.toolCalls.length > 0 && result.reasoning` 时，agent.run() 把 `{text: result.reasoning, signature: result.reasoningSignature, model: 当前模型}` 写进 push 的 assistant 消息；最终回答消息不写（与 DSH "tool-call-free turns dropped" 对齐）。
- **捕获签名**：`anthropic.ts` SSE switch 增加 `signature_delta` 分支（`d.type === "signature_delta"` → `signature += d.signature`），当前该事件被 default 吞掉。
- **存档**：SessionData.messages 直接序列化 ChatMessage，可选字段自动持久化；旧存档无此字段天然兼容，载入即用。

### 2.3 回传规则（按路线分）

**openai 路线（DeepSeek 等）**：

- `toSdkMessages` 对带 `thinking` 的 assistant 消息输出 `reasoning_content: thinking.text` 字段。
- 受 config 开关 **`REASONING_PASSBACK`（默认 off）**：默认关的理由是 §0.3-2 实测不回传也无 400，关着省 token；若未来 DeepSeek 收紧校验，置 on 即合规，零代码改动。开关仅在 effort≠default（思考模式）时生效，与 DSH 的 "required in thinking mode" 对齐。

**anthropic 路线**（修 §0.3-1，默认开启，无开关）：

- `toAnthropicMessages` 把 assistant 的 `thinking` 转为 `{type: "thinking", thinking: text, signature}` 块，**置于该消息 blocks 首位**（Anthropic 要求 thinking 先于 text/tool_use）。
- **回放对齐规则（照抄 ReplayEnvelope 思想）**：
  - `thinking.model === 当前请求模型` → 带签名回放（签名逐字，包括空签名）；
  - 模型不一致（换 provider/模型后载旧会话）→ **不带 thinking 块**（"foreign history carries no invented signature"，绝不伪造签名）;
  - `signature` 缺失 → 降级为不带该块 + `ui.printInfo` 告警一次（"思考签名缺失，已从历史省略，官方端点多轮工具可能报错"）。
- 回放范围：只需覆盖**带 toolCalls 的 assistant 消息**（即 tool_result 前一条）——这正是 API 的校验点，也与存储条件一致。

**与压缩的交互**：主文档 M3 压缩物理移除老轮次，thinking 随之消失——回传规则不受影响（DSH 同款结论，无需特殊处理）。

### 2.4 辅助调用关思考

- **不需要新字段**：压缩总结调用（主文档 §3.4）构造自己的 ChatParams 时显式 `effort: "off"`（openai 路线 → `thinking:disabled`；anthropic 路线 → 不发 thinking 参数）。未来 session-title 类调用同规矩。
- 好处：辅助调用不付思考成本、思考流不串进前端主会话展示、总结更快。

### 2.5 token 计数

- `estimateBreakdown`（tokens.ts）的"消息"类必须覆盖回传的 `assistant.thinking.text`——回传时它真实消耗输入 token，不计数会破坏"六类和 = promptTokens"的 withOther 校准不变量（tokens.test.ts 已有此风格单测）。
- **计数条件与回传条件严格对齐**（同一个开关判断、同一个 toolCalls 判定），避免"计了不发"或"发了不计"的漂移。

### 2.6 UI

- 思考流展示不变（现状已好：运行中展开、完成折叠、标题带字数）。
- 可选：/status 加一行"本会话回传思考 N 次"（审计性质，非必须）。

## 3. 里程碑与验收

| 里程碑 | 内容 | 验收标准 |

| **M3 openai 开关** | REASONING_PASSBACK 配置 + toSdkMessages 条件输出 | 开关矩阵单测；默认 off 行为与现状逐字节一致 |
| **M4 辅助关思考** | 压缩调用 effort:"off"（与主文档 M3 会师，若压缩未做则先落在本仓库测试桩上） | 辅助调用请求体不含 thinking/reasoning 参数 |
| **M5 计数对齐** | estimateBreakdown 覆盖 thinking.text，条件与回传对齐 | 六类和不变量单测（含/不含回传两种开关态） |

每里程碑：`npm run typecheck` + `npm test` 全绿；新测试文件加进 package.json。

## 4. 风险与开放问题

1. **M2 修复的紧迫性取决于使用面**：只用 DeepSeek 则 M2 不炸；一旦有人用 Anthropic 官方 key 开思考跑工具循环就会撞上。建议 M2 先行。
2. **存档体积**：思考只在 tool 轮存，但 32k budget × 多轮仍可观。开放问题：thinking.text 超 16k 字符时是否中间截断（签名仍全量存）？——先不做，观察到存档膨胀再说。
3. **REASONING_PASSBACK 默认 off 的前提**是"DeepSeek 实测不回传也无 400"持续成立；一旦模型/网关行为变化（出现 400），开关置 on，同时回主文档 §3.4 检查压缩与它的交互。
4. **空回复守卫的交互**：纯思考回复已被守卫不入历史（agent.ts:185），thinking 存储只发生在有 toolCalls 的分支，无新增中毒路径。
