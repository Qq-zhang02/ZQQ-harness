## 0. 需求拆解（用户原话）

> 「我需要子代理详情的下拉方框的自动收起与普通对话的模式一致，方框内内容完成后自动收起，而不是全都展开最后才统一收起」

### 0.1 排查结论

普通对话（主对话）的折叠语义（index.html 既有代码）：

| 块类型 | 展开时机 | 收起时机 |
|---|---|---|
| 工具块（.tblock） | 调用出现（addTool，live 展开式） | **结果一到达立即收起**（`addToolRes` 末尾 `classList.add("collapsed")`） |
| 思考块（.think） | 流式产出中（live） | **该消息开始产出正文/工具调用即收起**（onContentDelta 首次与 addTool 开头都调 `endThink()`→collapsed） |
| 历史渲染 | — | renderHistory 全收起 + 轮末 foldTurns 收纳 |

子代理详情时间线（makeTimeline）的旧默认规则：**「最后一条 assistant 组的思考/工具块全部展开，其余折叠」**（`open = i === lastAsst`）。运行中跟随（贴底、keepOpen=null）时每 1.5s 轮询重建都按此定态——**最后组里已完成（结果已到达）的工具块也保持展开**，直到下一组 assistant 消息出现才整体收起 = 用户看到的「全都展开、最后才统一收起」。完成后存档视图同理：最后组全展开。

### 0.2 定案

**默认展开规则改为逐块「完成即收起」，与普通对话 addToolRes/endThink 逐字对齐**（仅改 `defOpen` 的计算，`isOpen` 优先级链 explicit > keepOpen > defOpen 不动）：

| 块类型 | 新 defOpen |
|---|---|
| 工具块 | `tc.id ? !answered.has(tc.id) : false`——answered=transcript 里 tool 消息的 toolCallId 集；**结果未到达（运行中）→ 展开；到达 → 收起** |
| 思考块 | `thinkingOnly = i === lastAsst && i === messages.length - 1 && !m.content && 无 toolCalls`——**该消息是最后一条（仍在产出）且尚无正文与工具调用（纯思考中）→ 展开；一旦产出正文/调用/消息不再最后 → 收起**（endThink 语义的 transcript 等价） |

推论（全部符合「普通对话模式」）：
- 任意时刻默认展开的只有**进行中的块**（正在流式的思考 / 结果未回的工具调用）。
- 完成后存档视图：全部收起、报告正文（answer 不在折叠块里）照常可见——与普通对话历史「过程折叠、答案可见」一致。
- 回看（未贴底）keepOpen 冻结展开集：**正在读的块不因完成而塌掉**（docs/11 W2 的阅读位置保护不回归）；贴底跟随 keepOpen=null：新完成的块在下一轮轮询（≤1.5s）即时收起（跟随者要的是尾部可读——docs/11 §1.6.3 设计意图的自然延伸）。
- 手动开关 explicit 优先级最高，重渲染间保持（既有语义不变）。

保底视图（buildLiveTimeline，存档读取失败时的步骤流）同规则对齐：`answered` 从步骤流的 toolResult 事件构造，tool 事件对应块 `!answered.has(s.id)`。

### 0.3 明确不做（边界）

- 不给时间线加「轮末 🔧 执行过程」整体收纳（普通对话的 foldTurns 依赖 DOM 轮次边界，时间线是整体重建模型，逐块收起已达成同等可读性；加收纳=引入双层层级，回看冻结的 key 语义也要重设计——成本大于收益）。
- 不改普通对话侧任何代码（对齐方向是时间线向普通对话看齐）。
- 贴底跟随下完成收起引起的高度减小不做「保持高度」补偿（跟随者本就在底部，rebuildKeepScroll pin→autoscroll 兜底；docs/11 的防跳变只针对未贴底回看，且由 keepOpen 冻结覆盖）。

## 3. 已知边界（诚实声明）

1. 思考块的「流式展开」依赖服务端 transcript 暴露**进行中**的 assistant 消息（纯 thinking 增长阶段）；若服务端只在消息定型后才入 liveMessages，思考块将直接以收起态出现（收起本身正确，只是少了「看着思考流式长大」的过程——与既有一致，无回归）。
2. 时间线工具块无 live「运行中⋯」状态标（普通对话有 .tblock.live 的 tstat 动画）——运行中块以「展开+尾部『…运行中』note」呈现，既有行为，本轮未动。
3. 长工具执行（如 pwsh Start-Sleep）的运行中窗口内块展开、结果到达后 ≤1.5s 收起——由轮询粒度决定，非事件驱动（时间线是拉模型，docs/8 定架）。
