## 2. 核心决策：「无构建」≠「单文件」

docs/21 §5-6 不变量的实质是**禁止 node_modules 构建链**（含前端 npm 依赖）。而三个**零构建能力**是现成的：

1. **浏览器原生 ES Modules**：`<script type="module" src="/app/main.js">` 同源加载、原生 import——无需打包器；module 默认 defer，与现状"脚本置于 body 尾部"时序等价；
2. **Node 原生 import .js**：node:test 直接 `import("./replay.js")`——前端逻辑**首次可单测**（登记 package.json 显式测试清单即可，.js 也能进 `node --test`）；
3. **tsc 的 checkJs**：JSDoc 注释即类型，`tsconfig.frontend.json`（allowJs + checkJs + DOM lib）单独跑——拿到 ~80% 的 TS 价值，零构建。

因此 F 线的形态是：**纯逻辑进 `src/web/public/app/*.js`（可测模块），视图层暂留 index.html（F4 再拆）**。不变量的正式修订（"无构建单文件" → "无构建：原生 ES Modules，禁止 node_modules 构建链与前端 npm 依赖"）在 **F4 实施时**才做——F1–F3 期间 index.html 仍是可独立运行的单文件（只是 import 了同目录模块），README 无需中途改口。

- **不变量正式修订**（docs/21 §5-6 + README 架构节同步）："无构建单文件前端" → "**无构建前端：原生 ES Modules；禁止 node_modules 构建链与前端 npm 依赖；`app/` 模块间 import 必须相对路径**"。
- 模块间依赖必须无环（ESM 天然强制显式依赖——这是对现状"全在一个作用域"的直接改善）；web-static 模块的"新增文件需重启"提示写进 README 开发节。

**验收**：拆后 index.html ≤500 行（骨架+CSS）；全部测试/哨兵联动更新；活服 + 打包版（若 DT2 已完成）双冒烟。

> **实施结果（2026-11-16，已完成）**：验收三项全过（index.html 2,906→473 行；哨兵七处联动；活服 12/12 + win-unpacked 打包版双冒烟）。**与草案的偏差**：五文件落地为**七模块**——无环约束下 main 不能持有 chatStore/applyState/refreshSnapshot（区域模块反向依赖成环），故新增 `state.js`（三区共享状态仓）与 `chat.js`（消息渲染层）两个共享层；sidebar→main 的 switchSession 依赖经 `bindSessionSwitch` 回调槽破环（详见头部 F4 实施记录①）。

## 8. 与桌面端的统一编排（本文档核心）

### 8.1 依赖图

```
DT0 服务端就绪化 ──→ DT1 壳落地 ──→ DT2 打包分发 ──┬→ DT3 桌面增强（通知项依赖 F1）
（docs/25 §5）                                    └→ （托盘/自启无前端依赖，随时可做）
F1 纯逻辑抽离 ──→ F2 store 化 ──→ （F3 长期渐进，任意时点插入；F4 条件触发）
     │
     └─ web-static 模块（/app/*.js 静态服务）──→ DT2 打包验收须含"app/*.js 加载"检查项
```

**硬依赖只有两条**：① DT2 的产物校验清单加一条"打包版加载 `/app/<模块>.js` 成功"（若 F1 已落地；electron-builder files 已含 `src/**/*`，app/ 自动进包，验的是事实而非配置）；② DT3 的"审批通知"是**前端** Notification 功能（`http://127.0.0.1` 是 secure context，渲染进程直接可用，零壳代码），排在 F1 之后做（落在模块化前端上）。其余全部可独立推进。

### 8.2 四梯队建议顺序（单人串行的现实编排）

| 梯队 | 内容 | 工时 | 出口验收门 |
|---|---|---|---|
| ① 地基 | **DT0**（半天，docs/25 §5）→ **F1**（1.5 天，§3） | ~2 天 | DT0 三项验收 + F1 新增测试全绿 |
| ② 桌面形态 | **DT1 壳落地**（1 天）→ **DT2 打包**（1 天，验收含 app/ 加载检查） | ~2 天 | 干净环境安装→全流程冒烟通过 |
| ③ 质量（长期渐进） | **F2**（1 天）→ **F3** 逐点（每点独立可停） | 弹性 | 每区/每点独立验收 + 全量回归 |
| ④ 增强/条件 | **DT3**（通知依赖 F1；托盘/自启独立）与 **F4**（条件触发） | 按需 | 各自验收 |

**串行原则**：任何时刻只动一条线；前端大改（F1/F4）与打包发布（DT2）**错开**，打包前跑全量冒烟（`npm test` + smoke 系列 + 手工清单）；每阶段独立 commit、独立补实施记录。

### 8.3 共享基建与零漂移重申

- **web-static 模块两线共用**：浏览器直开与桌面渲染进程加载的是同一份 `/app/*.js`；
- **双入口零漂移**（docs/25 §8-2 重申）：`npm run web` 与桌面壳跑同一份 server.ts 与同一份前端——任何"只给桌面"的行为分支先问能否做成两端共享的服务端/前端能力；
- 前端改动的哨兵联动（§3.2-3）对两线同等生效。

## 9. 统一维护纪律与不变量（F 线 + DT 线合并，任何改动不得破坏）

1. **壳不进业务**（docs/25 §8-1）：desktop/ ≤2 文件、主进程不 import `src/**`、不读写业务数据文件。
2. **双入口零漂移**（docs/25 §8-2 + §8.3）：浏览器与桌面同一份代码；DT0 的 127.0.0.1 默认绑定是唯一声明的行为变化。
3. **Electron 升级核对单**（docs/25 §8-3）：内置 Node ≥22.18（type-stripping）→ 干净机冒烟 → builder 兼容。
4. **壳不进 `npm test`**（docs/25 §8-4）：GUI 用打包后手工清单 + 零 token 桩。
5. **（F 新增）app/ 零依赖**：禁止 import node_modules 与任何 `https://` 远端模块（哨兵锁定）；模块间 import 一律相对路径。
6. **（F 新增）纯逻辑模块禁 DOM**：replay/turns/autoreport/store 不得引用 `document`/`window`（可测性边界，静态断言）；需要 DOM 的代码属于视图层（F4 前留在 index.html）。
7. **（F 新增）行数防回涨**：F1 完成后设 index.html 内联 script 行数上限哨兵（当时实测值 +10% 取整），防止新功能又堆回单作用域。
8. **（惯例）**：新增 .test.js 须登记 package.json 显式清单（docs/22 踩坑记录）；每阶段 typecheck + 全量测试 + 手工冒烟；实施记录写本文档头部。
