# 交接文档：多会话并行与「运行中切换对话」显示问题

> 更新：2026-09-23。本文档面向后续接手「多会话并行 + 运行中切换显示」问题的开发者/会话。
> 阅读前提：了解项目根 README 的「Web UI / 命令审核 / 沙箱」三节；本文只讲多会话这条线。

## 0. 一句话现状

多会话并行与运行中切换已实现并验证；**切回运行中的会话"显示不出来/显示不全"的根因已定位并修复**
（见 §3），修复方式是"完整快照 + ml 过滤在途重放"。若问题复现，按 §5 诊断流程走。

## 1. 架构（改动在哪）

### 服务端 `src/web/server.ts`（2026-09-23 重写）

- **每会话一份运行态 `SessionRuntime`**，常驻 `runtimes: Map<id, rt>`，不淘汰：
  `agent / llm / providerId / settings{alwaysConfirm,effort,askMode,sandboxMode} / totals / auditEvents /
  compactions / skills / mcp(McpManager) / registry(ToolRegistry) / busy / abortCtl / pendingApproval / turnInfo`
- `viewId` = "正在查看"的会话；`viewSeq` = 单调递增的视图切换序号（随 sessions 广播下发）。
  **切换视图只改 viewId，后台会话继续运行**（可多会话同时各跑各的轮）。
- 每个 runtime 一个 `Agent` + 一个 `AgentUi`（makeUi(rt)）：**所有 SSE 事件带 `sessionId`**；
  delta/tool/toolResult 还带 **`ml` = 发出时 `agent.messages.length`**（前端判重用，见 §3）。
- 每个 runtime 一个 `ToolRegistry` + 一个 `McpManager`（**同工作区多会话会各自启动一份 MCP 服务器进程**，
  简单正确优先；若要改共享需先确认 client.ts 的 JSON-RPC 并发安全）。
- 轮锚点：`startTurn` 记 `rt.turnInfo = { ml: messages.length, userText: text }`，随 state 广播
  （`currentState().turn`），轮结束（finally）清空。当前前端已不依赖它做重放（见 §3），仅作信息保留。
- 所有"busy 409"只看**目标会话自身**的 busy（chat/settings/compact/activate=当前查看会话；
  providers/delete=任一 busy 会话在用；workspace/delete=该工作区有 busy 会话）。
  `purge` 拒绝 busy 或正在查看的会话；**空闲的内存缓存连带删除**。

### 关键端点

| 端点 | 说明 |
|---|---|
| `POST /api/sessions/load` | 核心切换。目标在内存→直接切视图（**不从磁盘重载，运行态不丢**）；否则从磁盘装载并建 runtime。响应体**直接返回** `{sessionId, messages, state}`（前端渲染用它，不依赖 SSE 时序） |
| `POST /api/chat` | 目标=当前查看会话；仅当**它** busy 时 409 |
| `POST /api/stop` | body.sessionId 指定中止谁 |
| `POST /api/approval` | body.sessionId 路由到对应会话的 pendingApproval |
| `GET /api/sessions` | payload 含 `current`、`viewSeq`、`running[]`（busy 会话 id 列表，侧边栏 ⏳ 用） |

### SSE 事件（全部带 sessionId）

`delta(kind,text,ml) / tool(name,preview,ml) / toolResult(output,meta,ml) / usage / info / error /
compaction / approval / state(含 turn) / turnEnd / init / sessions`

`init` 只出现在两处：**新 SSE 连接的快照**（sseHandler）与**压缩后历史被物理替换**（onCompaction）。
视图切换**不广播 init**（历史上它造成同一快照双渲染=闪烁，已删）。

### 前端 `src/web/public/index.html`

- `viewId`（当前查看）+ `sessCache: Map<id, {buf, loading, approval, needsRefresh, turn}>`。
- **事件路由 `route(evName, d, render)`**：`d.sessionId === viewId && !loading` → 直接渲染；否则：
  state/usage 只更新缓存；turnEnd 清 buf+approval（后台轮结束=历史已完整）；其余 push 进 `c.buf`。
- **切换 `switchSession(id)`**（sitem 点击与跟随都走它）：
  乐观置 viewId → `loading=true` → `POST /api/sessions/load` → **渲染完整快照** →
  重放 buf 中 `ml >= msgs.length` 的在途事件（§3）→ `needsRefresh = busy` → finally 复位。
- **跟随逻辑**（sessions 事件）：只跟随 `d.viewSeq > viewSeqSeen` 的事件；进行中（switchingTo）时记
  `pendingFollow{id,seq}`，完成后仅当 `seq === viewSeqSeen` 仍最新才补跟随。

## 2. 已发生并修复过的四个 bug（按时间序）

1. **视图错位 → 误停后台任务**：服务端切了视图（新建/切工作区），客户端 viewId 没跟 → 用户消息
   走了"busy→停止"分支把后台任务中止。修复：sessions 广播处理里跟随 current（后升级为 viewSeq）。
2. **乒乓循环 = 页面闪烁（用户报告"切换闪烁无法操作，刷新暂时解决"）**：switchView 里
   "先归档旧视图再切视图"，归档附带的 sessions 广播携带**旧 current** → 客户端跟随逻辑据此回切 →
   服务端再广播 → 无限往复，聊天区反复清空重建。
   修复四件套：①服务端**先切 viewId 再归档**（广播恒为新值）②删视图切换场景的 init 广播
   ③viewSeq 序号去重 ④switchingTo 抑制 + pendingFollow 带序号补跟随。
3. **切回运行中的会话显示不出来/不全（用户再次报告，本文档主线）**：见 §3。
4. **删除当前视图会话 → 服务进程崩溃（2026-09-23 端到端测试发现）**：三重叠加——
   ①`/api/sessions/delete` 在 `runtimes.delete(id)` **之后**调 `viewRt()`，map 被删空时
   `[...values()][0]!` 断言拿到 undefined → TypeError；②`broadcast()` 对已断开/销毁的 SSE
   连接 `res.write` 同步抛错且无保护，异常沿当前请求处理器外抛；③外层 catch 用
   `json(res, 500)` 兜底，但此时 headers 已发出 → `ERR_HTTP_HEADERS_SENT` 从 catch 里再抛 →
   未捕获异常 → **进程退出**（页面刷新重连 SSE 时竞态触发概率最高）。
   修复三件套：①delete 先取 `target.workspace` 再删（不再事后调 viewRt）②broadcast/send
   逐客户端 try/catch，失败即从 sseClients 剔除 ③外层 catch 检查 `res.headersSent`，
   已发出只 `res.end()` 不再写头。
   **教训：广播写流必须逐连接容错；外层 catch 必须防二次故障，否则兜底本身就是崩溃点。**

## 3. 「切回运行中对话显示不出来」：根因与修复

### 症状

会话 A 任务运行中切到 B，再切回 A：转写空白/缺内容（尤其缺切换期间的过程），或整页无内容。

### 根因（两代实现各有一个）

- **第一代（缓冲+锚点截断）**：切回时渲染 `messages.slice(0, 轮开始时长度)`，再重放客户端缓冲。
  两个洞：**页面刷新后缓冲为空**（刷新前流过的事件永久丢失）；缓冲只覆盖"切走之后"的事件。
  二者叠加 → 快照被裁掉本轮已完成部分 + 缓冲补不上 = **近乎空白**。
- **测试环境干扰（排查时反复误导）**：IAB 里被释放的旧标签页仍开着旧 JS（EventSource 自动重连），
  会按旧跟随逻辑抢视图、发 load 请求，让服务端视图来回跳。**排查前必须 `tabs.list()` 清场**。

### 最终修复（当前代码）

**原则：服务端完整历史是唯一事实，快照永远全量渲染，绝不因"运行中"而截断。**

1. 服务端 makeUi 给 delta/tool/toolResult 附 **`ml`（发出时 agent.messages.length）**。
2. 前端 switchSession：**`renderHistory(全部 messages)`**（含本轮已完成轮次——服务端历史天然完整，
   永不空白）；然后把缓冲按 `d.ml >= msgs.length` 过滤后重放——ml 小于快照长度的事件内容已
   在快照里（跳过防重复），ml==长度的是**在途流**（未落入历史的思考/回答增量、进行中的工具块）→ 重放。
3. `needsRefresh = busy`：轮结束（turnEnd）后自动再拉一次快照，保证最终态精确。
4. 兼容：approval/info 事件无 ml → 恒重放（审批卡绝不丢）。

### 验证基线（2026-09-23 全部通过）

- 空闲 8s：0 渲染、视图不动（无乒乓）。
- 运行中快速来回点击 6 次：恰 6 次 renderHistory（计数器+调用栈确认），计数随后冻结，最终视图=最后点击。
- 长任务（12s pwsh）运行中切走→切回：**立即**显示用户消息+工具块（非空、无重复用户消息），任务完成可见。
- 后台完成后切回：完整历史渲染。
- typecheck + `npm test` 121 项全绿。

## 4. 若问题复现：诊断流程

1. **确认两端代码版本一致**：服务重启过没有？（改了 .ts 必须重启；index.html 刷新即得）旧服务端
   不发 ml/turn 字段 → 前端降级路径行为不同。
2. **服务端事实优先**：`GET /api/sessions` 看 `current/running`；直接查
   `~/.ZQQ-harness/sessions/<id>.json` 的 messages（服务端历史完整=客户端渲染问题）。
3. **清场**：浏览器 `tabs.list()` + `user.openTabs()`——关掉所有旧 8787 页面再测（僵尸页面抢视图）。
4. **页面内探针**（evaluate）：
   - 渲染计数：包一层 `renderHistory` 统计调用次数与调用栈——正常=每次切换恰 1 次；
     空闲时增长=乒乓循环仍在。
   - `switchSession(id)` 直接调用 vs 点 sitem：区分"切换逻辑坏了"还是"点击链路坏了"。
   - 看 `POST /api/sessions/load` 响应：`messages` 是否完整、`state.busy/turn` 是否符合预期。
5. **常见症状对照**：
   - 空白 + viewId 正确 → load 响应 messages 为空/渲染抛异常（看 Console）；
   - 视图来回跳 → viewSeq/跟随逻辑（检查是否两端版本一致）；
   - 内容缺失但非空白 → 检查 buf 重放的 ml 过滤（`x.d.ml >= msgs.length`）与 turnEnd 的
     needsRefresh 是否触发。

## 4.5 工具块"运行中"残留与游离结果行（2026-09-23 用户报告，已修复）

**症状**：MCP 工具明明调用完成，块仍显示"运行中⋯"；工具结果 JSON 以 `↳ {...}` 游离行出现在块外面。

**根因**：前端用**单一全局光标 `curTool`** 把 toolResult 配对到最近的 toolCall 块。两种真实场景会错位——
①一条 assistant 消息带**多个 toolCalls**（并行调用）时，块 A、B 依次创建，结果 A 先到却填进光标
指向的 B 块，结果 B 落到 `else` 分支变游离 `↳` 行，A 块永远"运行中"；
②**运行中切走再切回**：快照 renderHistory 已为在途 toolCall 建了块，缓冲重放的同名 tool 事件
又建一个重复块，光标指向重复块，真结果填重复块，快照块残留"运行中"。

**修复**：SSE `tool`/`toolResult` 事件与 `AgentUi.printToolCall/printToolResult` 增加 **callId**（即
toolCall 的 id，历史消息里天然有 `tc.id`/`m.toolCallId`）；前端 `toolBlocks: Map<callId, 块>` 按 id
配对——addTool 对已有 id 直接复用（重放去重），addToolRes 按 id 找块（找不到才退回光标，再找不到
保留游离行兜底）；`finishSegments`（轮边界/切换/重渲染）清空映射。页面内已验证：并行调用、乱序
结果、重放去重、无主结果兜底四场景全过，真实 MCP 轮无残留。

**二次修复（用户实测仍复现后的真正根因，同日）**：用户"多次调用 MCP 仍显示运行中"的两个根因——
①**被中断轮的存档里 toolCalls 数 > tool 结果数**（停止/出错导致部分调用永远没有结果），
renderHistory 把"没有结果的调用"一律画成 live"运行中"，导致每次打开该会话永远转圈（实例：某会话
7 调用/3 结果 → 4 块永远转圈）。修复：renderHistory 预计算 answered 集合，**只有 `state.busy &&
最后一条 assistant` 的未答调用才渲染 live**（真的在途），其余渲染为折叠 + "无返回结果（本轮被中断
或调用未完成）"标注；②**turnEnd 收尾清扫**：轮结束时把 chat 里残留的 `.tblock.live` 一律去 live、
折叠并加同款标注（兜底任何漏配对路径）；③**`/` 页面响应加 `Cache-Control: no-cache`**——此前无
缓存头，浏览器可能长期跑旧版前端 JS，导致前端修复在用户侧"不生效"（排查时先强刷 Ctrl+F5）。

## 4.6 新建对话不出现在侧边栏（2026-09-23 用户报告，已修复）

**根因**：侧边栏渲染的是**磁盘存档列表**，而 `persistSession` 有"没有首条用户消息就不落盘"的守卫——
新会话在首轮结束前只存在于内存，点 ＋新对话 后看不到它，要等切换/存档后才出现。

**修复**：`newSessionForView` 创建会话时**立即写一份空存档**（title 空、messages 空；列表与前端都
回退显示"(无标题)"），首轮结束后 persistSession 用首条用户消息覆写标题。`/api/sessions/new` 本就
广播 sessions，于是新建即刻可见。取舍：空会话会留一个 "(无标题)" 条目（与主流 AI 对话产品一致），
✕ 两步确认可删。

**空占位堆积修复（同日，用户报告"来回切换工作区空白对话越来越多"）**：创建即存档的副作用是每次
切换都留下一个空占位。修复=**惰性清扫 `sweepEmptySessions()`**：`messageCount=0`、非当前视图、
运行时不在后台跑轮（运行中的马上就会有内容）→ 删档 + `removeFromOrder` 清排序；回收站里的空占位
（删工作区时产生）直接 purge、不进回收站。触发时机=**每次新建会话后**（newSessionForView /
bindWorkspace）+ **服务启动时**（顺带清理历史积累）。效果：来回切换任意次，侧边栏始终只有"当前
视图那一个"空会话；有内容的会话永不误删；`bindWorkspace`（启动后首次点工作区的引导绑定路径）也
补了创建即存档，当前会话同样立即可见。

## 5. 已知边界与设计取舍

- runtime 常驻不淘汰：单用户内存可承受；会话特别多时可加 LRU（淘汰仅限非 busy）。
- MCP 进程按会话隔离：同工作区 N 个会话 = N 份 MCP 服务器进程。
- 页面刷新时正在流的"在途片段"会丢（快照只有已完成消息）：轮结束自动补齐；本轮已完成轮次不丢。
- 轮内溢出压缩会物理缩短历史（罕见）：ml 过滤按当时长度判重，极端情况下切回视图可能有
  一条重复/缺失的视觉块，turnEnd 快照兜底修正。
- pwshTool 的升级额度（escalationCredits）是模块级、跨会话共享的。

## 6. 手动回归清单（改动本区域必跑）

1. 会话 A 发长任务（如 `Start-Sleep -Seconds 12`）→ 工具运行中切到 B → B 独立对话正常应答。
2. 运行中切回 A：**立即**看到用户消息+工具块（不空白、不重复）；完成后「完成」可见。
3. 快速来回点击 6 次：无闪烁、最终视图=最后点击、空闲后渲染计数冻结。
4. 后台会话 ⏳ 徽章出现/消失；审批卡只在自己会话视图出现、可批准且批准后执行。
5. 停止按钮只停当前查看会话；purge 回收站会话不被内存缓存挡住。
6. `npm run typecheck` + `npm test`（121 项）全绿。
