# 交接文档 20：协调者系统提示注入「子代理（worker）系统提示词说明」段

## 0. 需求（用户原话拆解）

> 把对应子代理具备的系统提示词（也包括 mcp 给到子代理的说明）也给到协调者，标注是子代理的系统提示词说明，相同的 AGENTS.md 提供的部分就放到子代理这部分里面说明，协调者本身就不要重复这部分了。

| 项 | 定案 |
|---|---|
| 注入内容 | 协调者系统提示新增 order 35 段「# 子代理（worker）系统提示词说明」——worker 共同系统提示的**同构重放**：基础规则（normal base 段）+ worker 职责段（WORKER_ROLE_SECTION）+ 可用工具行（audience=worker 的系统工具 summary，与 toolDocsOf 同款行式排序）+ 可加载技能清单 + MCP 服务器使用说明 + 两级 AGENTS.md 全文。包装头明确标注"引用自子代理侧，不是对你的指令"，并给出使用纪律（任务书与能力匹配、不派做不到的事、不在任务书里重复其中规则） |
| 不含部分 | 按派发参数逐 worker 变化的内容不重放：ws.system 自定义角色段、scope 写入范围、effort——包装头注明"按派发参数附加的任务角色段与写入范围不在其中" |
| AGENTS.md 去重 | `sections.ts` 两级 AGENTS.md 段（order 40/50）对 `sessionKind==="coordinator"` 渲染 null——全文只随子代理段出现一次，协调者自身不再单独注入（normal/worker 分支字节不变） |
| MCP 懒注入 | worker 的 MCP 说明随 `rt.mcp.instructionsText()` 惰性进入段内：协调者创建时未连接则自然省略；连接成功后 `workerMcpToolsOf` 触发 `rt.agent.refreshSystemPrompt()` 热更一次（promise 缓存保证恰好一次）。**连接时机见 §0.1 修订：会话创建即预热，不再等首个 worker 派发** |
| 惰性渲染 | 段 render 读 rt 当前状态（技能/AGENTS.md 文件/MCP 说明/提供方视觉），不缓存文本——setSkills/setVision 等既有 rebuild 自动带新，无需额外更新点 |
| 不变面 | 协调者 registry 仍四件（幻觉调 run_pwsh 照收「未知工具」）；worker 侧提示词零改动；普通会话提示词字节不变（sections 直传） |

## 0.1 第二轮修订（真机反馈：协调者并不知道子代理的 MCP）

第一轮的 MCP 懒注入有时序缺口：worker MCP 只在**首个 worker 派发时**才连接（docs/6 P2 原设计），连接后热更才补上说明书——**新开的协调者会话第一轮、以及重启恢复后在首个 worker 派发之前**，协调者对子代理的 MCP 能力一无所知。定案：

| 项 | 定案 |
|---|---|
| 创建即预热 | createRuntime 协调者分支（已绑工作区时）fire-and-forget 调 `workerMcpToolsOf`（不 await——MCP 握手最长 20s，不能阻塞会话创建）；连接成功后既有内部 refreshSystemPrompt 热更补上说明段。用户真正发首条消息前（本地 stdio 秒级连完）说明书通常已就位 |
| 绑定补预热 | bindWorkspace 协调者分支：`!rt.workerMcp` 时同样预热。createRuntime 对**未绑工作区的引导会话不预热**——此刻只有全局配置，连上会把"全局-only"缓存进 rt.workerMcp，绑定后工作区级 mcp.json 的服务器就丢了 |
| 红线不变 | 预热连接挂 rt.mcp（worker 共享），协调者自己的 registry 仍四件、不装 mcp__ 工具；MCP 故障降级 null（照旧不阻断派发），预热异常 `.catch(() => {})` 静默 |
| 暴露面 | `workerMcpToolsOf` 导出（原模块私有）供 session-runtime/session-lifecycle 预热调用 |

## 2. 关键决策与理由

- **重放"共同部分"而非逐 worker verbatim**：worker 提示词按派发参数变化（ws.system/scope/effort），静态注入只能取共同不变量；变化部分（任务角色段）本就出自协调者自己写的任务书，无需回显。重放走同一条 assembleSystemPrompt 装配线（含 subagent-role），与 mountWorkerAgent 同构——将来 worker 提示词改版，协调者视图自动跟随，不存在两处维护。
- **AGENTS.md 从"协调者+worker 各一份"收敛为"只在子代理段一份"**：内容本就逐字节相同，去重即用户要求；对协调者的语义没丢——它仍能读到全文（在子代理段内），且标注了"这是子代理遵循的指令"。
- **MCP 走懒注入而非预连接**：为拿 instructions 提前连接会把 MCP 服务器进程提前拉起（协调者会话可能从不派 worker），违背 docs/6 的懒加载设计；首连热更只重建一次系统提示，代价可忽略。
- **refresh 失败绝不影响 worker 装配**：实施中发现的真实坑——refresh 若放在 workerMcpToolsOf 的装配 try 内，测试桩 agent 缺该方法时异常被 catch 吞掉、worker 静默降级为不带 mcp__ 工具（P2 测试当场抓获）。修复：独立 try + 可选链，注释写明。

## 4. 遗留与建议

- 子代理段的工具行由 `SystemToolDef.summary` 直出（与实例侧 toolDocsOf 同源同排序）；若未来某个工具 create() 动态改 summary（当前没有此形态），两处会分叉——现状按 def 静态汇总是合理的。
- 惰性 render 每次重建重读两级 AGENTS.md 文件（rebuild 低频：技能热更/视觉切换/MCP 首连），量级毫秒，不做缓存。
- read_archive/view_image 等工具的 summary 已随之进入协调者视野（此前协调者不知道 worker 能读存档）——这是本需求的直接收益之一，无需额外动作。
